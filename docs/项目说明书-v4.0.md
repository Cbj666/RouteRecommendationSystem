## 一、项目概述

### 1.1 项目背景

城市慢跑与骑行正在从"个人锻炼"变成"日常出行方式"：武汉有东湖绿道、江滩、
环湖路等成熟路线，但现有地图产品回答的是"**从 A 到 B 怎么走、多远**"，
不回答"**这段路跑起来舒不舒服**"。

同一条 5 公里的路，可能一侧是林荫绿道、另一侧是双向六车道主干道；
同样 30 分钟，可能全程滨水，也可能要穿七个路口。这类差异无法用距离或时长表达，
需要一套**面向运动体验的环境评价**。

### 1.2 项目定位

> 给定起点、目标距离与偏好，给出**路段级的慢跑环境评分**，
> 并**推荐若干条闭合环线**，同时解释每条环线为什么好、差在哪。

不是导航产品（不做实时路况与转向指引），不是健身 App（不做训练计划），
也不是商业选址工具（不做房价、客群推断）。

### 1.3 与前一版（等时圈）的关系

| | v3.0 等时圈 | v4.0 慢跑适宜性 |
|---|---|---|
| 回答的问题 | 30 分钟**能到哪** | 这段路**值不值得跑** |
| 空间产物 | 面状等时圈 | 线状路段评分 + 闭合环线 |
| 核心方法 | 单源最短路 + 等值面 | 多准则综合评价 + 多目标路径 |
| 服务对象 | 通勤者 | 跑者 / 骑行者 |
| 复用资产 | — | 路网图、顶点索引、最短路内核、POI 统计、出图流程 |

研究方法是同源的（都在路网上做最短路与空间统计），
但目标函数、评价维度与输出形态完全不同，因此不构成重复选题。

## 二、项目目标与首版边界

### 2.1 总体目标

1. 建立一套**可解释、可复现**的路段环境评分体系（5 个维度，权重显式）；
2. 在武汉市域路网上完成**全量评分**（约 9.1 万段 / 4.7 万公里）；
3. 实现**闭合环线推荐**（目标距离 3 / 5 / 10 km，可按偏好调权）；
4. 提供**可交互的网页原型**：选起点 → 出环线 → 看解释。

### 2.2 首版必须实现

- [x] 路段评分：坡度、树冠、安全、过街、设施五维，输出 0–100 分与等级；
- [x] 环线生成：3 个起点 × 5 km 均能出闭合环线，单次 < 2 秒；
- [x] 每条环线给出：距离、用时、综合分、树冠占比、平均坡度、最近场馆距离；
- [x] 静态前端原型（1440×900），含地图、控制面板、结果面板；
- [ ] Vue 版可交互页面（下一阶段）。

### 2.3 首版边界

不做：

- 实时路况、空气质量实时值、天气；
- 个人体能模型与配速预测；
- 手机 App / 轨迹记录；
- 全中国推广（仅武汉，指标可移植但需重新标定）；
- 街景绿视率（数据不可得，理由见 6.3）。

## 三、目标用户与典型场景

### 3.1 目标用户

| 用户 | 关心什么 |
|---|---|
| 城市跑者（业余） | 从家门口出发能不能跑得舒服、有没有红绿灯折磨 |
| 周末休闲跑 / 骑行 | 哪条绿道值得专门跑一趟、停车与补给在哪 |
| 外地跑者 / 新生 | 不熟悉城市，需要"可信的推荐"而不是网红打卡 |
| 城市规划/课程评审 | 评分依据是否说得清、数据能不能复现 |

### 3.2 典型场景

1. **下班后 5 km**：从公司出发，优先避开车流与路口，绕一圈回原点；
2. **周末绿道**：目标 10 km，优先绿化与滨水，可以接受远一点的起点；
3. **两个起点对比**：住 A 小区还是 B 小区，哪个更适合日常跑步。

## 四、功能设计

### 4.1 起点与目标距离

- 地图点选或输入坐标；
- 目标距离 3 / 5 / 10 km（可扩展为自由输入）；
- 起点自动吸附到最近路网顶点，显示吸附偏差（当前中位 2 m）。

### 4.2 偏好权重

三个可调维度：**避开主干道**、**绿化/滨水**、**平坦**。
默认权重 0.39 / 0.39 / 0.23；权重直接影响路径代价，不是事后排序。

### 4.3 路段适宜性地图

- 全城 91,203 段，按 0–100 分着色（红→黄→绿）；
- 点击路段可看五个子分与原始指标（坡度、树冠、距主干道、路口数、最近场馆）。

### 4.4 环线推荐

- 每次返回至多 3 条候选，按综合分排序；
- 每条给出：距离、预计用时（10 km/h 基准）、综合分、树冠占比、平均坡度、
  最近场馆距离、起点吸附偏差；
- 支持"再来一批"（换折点方位）与"只要滨水/只要平坦"。

### 4.5 结果解释与导出

- 每条环线展开显示子分条与最差路段（"这 400 m 要过 6 个路口"）；
- 导出 GeoJSON（环线 + 评分属性）与 PNG（分享图）。

## 五、数据设计

### 5.1 数据源与规模

| 数据 | 来源 | 规模 | 用途 |
|---|---|---|---|
| 步行/可骑行路网 | OSM（Geofabrik 湖北提取） | 91,203 段 / 47,051 km | 评分与路径的骨架 |
| 高程 | SRTM 1″（AWS 公开，30 m） | 9 幅瓦片 | 坡度、爬升 |
| 地表覆盖 | ESA WorldCover 10 m（2021） | 4 幅瓦片 | 树冠覆盖率 |
| 运动场馆 | 高德 POI（`080100`） | 5,137 个，评分用 4,081 | 设施维度、地图点位 |
| 绿地/水体 | OSM landuse / water 面 | 4,900+ / 25,085 | 绿化代理、地图底图 |
| 公交地铁 | 高德（前版成果） | 591 线 / 231 站 | 起点接驳（可选） |

### 5.2 数据处理

1. 路网裁剪到武汉边界外扩 2 km（保留连通性），剔除高速与匝道；
2. 顶点按 1e-6 度去重，连续顶点成边，构建约 98 万节点的图；
3. 坡度：DEM 先做 150 m 高斯平滑，再求梯度（原始逐点差分会被建筑噪声放大到 5–7%）；
4. 树冠：WorldCover 类别 10（tree cover），120 m 窗口求覆盖率；
5. 所有长度在 EPSG:32650 计算，输出统一 WGS84。

### 5.3 数据边界（必须写进报告）

| 缺口 | 说明 |
|---|---|
| 街景绿视率 | 百度/高德不提供；腾讯需企业认证；Mapillary 中国区影像稀疏且约十年前 |
| 官方便民健身设施 | 公共数据平台仅江岸区有登记，且需备案系统才能下载 |
| 路段车流量 | 无公开数据，用道路等级 + 距主干道距离 + 路口密度代理 |
| 路面材质 / 照明 / 人行道 | OSM 覆盖率 4.3% / 0.9% / 0.2%，不可用 |
| 真实跑步轨迹 | 无公开接口，不做行为验证 |

## 六、评价指标体系

### 6.1 五个维度

| 维度 | 权重 | 计算 | 数据 | 方向 |
|---|---:|---|---|---|
| 安全（避开机动车） | 0.30 | 道路等级映射 + 距主干道 <50 m 扣分 | OSM | 越高越好 |
| 绿化 | 0.25 | 0.7×树冠覆盖（指数变换）+ 0.3×到绿地距离 | WorldCover + OSM | 越高越好 |
| 坡度 | 0.20 | 平均坡度，10% 记为 0 分 | SRTM | 越平越好 |
| 过街 | 0.10 | 200 m 内路口数，每多一个扣 7 分 | 路网自算 | 越少越好 |
| 设施 | 0.10 | 到最近运动场馆距离，`100·e^(−d/500)` | 高德 POI | 越近越好 |

综合分 = Σ 权重 × 子分（0–100），分档：差 <40、一般 40–55、较好 55–70、好 70–85、很好 ≥85。

### 6.2 为什么是这五个维度

- 对应跑者最常抱怨的五件事：**吸尾气、暴晒、爬坡、等红灯、没水没厕所**；
- 每个维度都有对应的可获取数据，且能说清误差方向；
- 权重显式写死，答辩时可现场改成 AHP / 熵权法重算。

### 6.3 代理指标的性质

- **绿化**：WorldCover 反映**成片林荫**，单排行道树不足一个 10 m 像元，往往未计入；
  因此加了"到绿地距离"做兜底。它不等于街景绿视率，但不受拍摄点影响。
- **安全**：没有车流量，用道路等级与主干道距离代理，误差方向是
  "对小路乐观、对辅路悲观"。
- **设施**：高德 POI 覆盖好于 OSM，但仍以商业与公共场馆为主，
  社区健身角（户外器材）覆盖不足。

### 6.4 现状分布

- 中位 **48.8**，10–90 分位 **32.4–58.7**；
- 武大片区均值 64.3、磨山 70.2、汉口老城约 52；
- 红色集中在跨江桥与快速路两侧，绿色落在东湖绿道、珞珈山、沙湖公园一带。

## 七、环线算法

### 7.1 思路

模仿跑者的真实决策：**跑到一半的地方折返，但回来不走原路**。

1. 沿路网计算从起点出发的距离场，取 0.44–0.56 倍目标距离处的节点作为候选折点；
2. 按方位角选 8 个方向各取一个，保证候选在空间上分散；
3. 去程：按偏好代价最短路（`代价 = 距离 × (1 + (100−子分)/40)`）；
4. 回程：把去程用过的边（**双向**）代价放大 4 倍，再从折点最短路回起点；
5. 只保留总长在目标的 85%–115% 之间的环线，去重后按综合分排序。

### 7.2 复杂度与性能

- 图规模：979,351 节点 / 2,075,761 条有向边；
- 单次请求：1 次距离场 + 1 次去程 + 8 次回程 Dijkstra ≈ **1.2 秒**；
- 图缓存 37 MB，加载 0.4 秒。

### 7.3 已知局限

- 环线形状偏"绕街区"，不如人工设计的绿道环线漂亮；
- 目标距离 3 km 时候选折点少，偶尔只有 1–2 条可选；
- 目前不惩罚"回头率"以外的重复经过（同一路口经过两次不会被识别）。

## 九、网页交互设计

### 9.1 页面布局

三栏：左侧控制（起点、距离档、偏好开关、生成按钮）、中间地图（评分路网 + 环线）、
右侧结果（综合分、六项指标、三个子分条、数据说明）。

### 9.2 核心流程

```text
选起点 → 设 3/5/10 km → 调偏好 → 点击生成
   → 地图叠加 3 条候选环线 → 右侧展示最佳环线指标
   → 切换候选查看差异 → 导出 GeoJSON / PNG
```

### 9.3 可视化要求

- 评分色带固定为红（差）→ 黄（中）→ 绿（好），图例常驻；
- 环线用深色实线压在评分底图上，起点用描边圆点；
- 数据口径（来源、代理性质）在地图角落常驻一句。

## 十四、预期成果与项目特色

### 14.1 预期成果

1. 一份可复现的评分数据集（9.1 万段，含五个子分与原始指标）；
2. 一个环线推荐内核（Python，1.2 秒/次）；
3. 一个可演示的网页原型；
4. 说明书 + PPT + 数据报告。

### 14.2 项目特色

- **不是再画一张热力图**：每个分数都能拆到五个可获取指标，能解释"为什么低"；
- **代理指标说清楚**：街景不可得、车流无公开数据，这些限制被写进方法而不是藏起来；
- **同一份路网，两种视角**：前版算通勤可达性，本版算运动体验，方法论可迁移。

## 十五、结论

在"没有真实跑步轨迹、没有街景、没有官方设施清单"的数据条件下，
本项目用三条公开可复现的数据链（OSM 路网、SRTM 地形、ESA 地表覆盖）
加一份商业 POI，构建了可解释的慢跑环境评价体系，并落成可演示的原型。

它的价值不在"绝对准确"，而在**「指标怎么选、权重怎么定、误差在哪」全部透明**——
这也是课程项目能站得住的地方。
