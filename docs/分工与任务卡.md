## 二、六个待认领工作项

> 每项都是**独立可交付**的，互不依赖（个别标注了前置）。建议按兴趣认领，
> 冲突时由组长协调；每人认领后先写三行"我要怎么做"，再动手。

---

### 卡片 1：可交互前端（Vue 3 + 百度地图）

**目标**：把静态原型变成能点、能改、能重算的页面。

**具体任务**
1. Vite + Vue 3 脚手架，复用 `frontend/prototype/index.html` 的视觉；
2. 接入百度地图 JS API（底图 + 坐标转换 WGS84→BD-09）；
3. 地图点选起点 → 调接口 → 画 3 条候选环线 + 评分底图；
4. 距离档（3/5/10 km）与三个偏好开关联动重算；
5. 右侧结果面板显示综合分、六项指标、子分条。

**交付物**：`frontend/` 可运行项目 + 一段 30 秒录屏 + 部署地址（可选）

**验收**
- 改起点后 3 秒内出结果；
- 环线与评分底图对齐（无偏移）；
- 1440×900 与 390×844 无横向滚动。

**先读**：`docs/design-guidelines.md`、`frontend/prototype/index.html`、`backend/app/running.py`
**前置**：接口未就绪时先用 `loops.geojson` 静态数据跑通
**预计**：3–4 人日

---

### 卡片 2：FastAPI 后端接口

**目标**：让前端通过 HTTP 调用，而不是读死文件。

**具体任务**
1. `app/api.py`：`POST /api/loops`（起点、距离、权重 → 环线 GeoJSON）；
2. `GET /api/segments`（bbox → 评分路段，供地图着色）；
3. `GET /api/facilities`（bbox → 场馆点）；
4. 启动时加载图缓存常驻内存，避免每次重建；
5. Swagger 文档 + 简单鉴权（可选）。

**交付物**：`uvicorn` 启动即用 + `curl` 示例 + OpenAPI 页面截图

**验收**
- 单次 `/api/loops` < 3 s；
- 并发 5 个请求不崩；
- 参数非法返回 400 而不是 500。

**先读**：`backend/app/running.py`、`backend/scripts/run_loop_demo.py`
**前置**：无（图缓存已在 `data/processed/running/graph/`）
**预计**：2–3 人日

---

### 卡片 3：评分验证与敏感性分析（答辩防线）

**目标**：回答"你的权重是不是拍脑袋""评分准不准"。

**具体任务**
1. 权重 ±20% 扰动，统计路段排序变化（Spearman 相关、前 10% 重合度）；
2. 与外部参照对照：已知绿道（东湖绿道、江滩）评分是否显著高于全市均值；
3. 对比 AHP / 熵权法给出的权重，看排序是否稳定；
4. 分城区 / 远城区讨论，避免用全市均值掩盖差异。

**交付物**：`docs/验证与敏感性分析.md` + 3 张图（权重扰动、对照箱线、分区分组）

**验收**
- 能明确回答"权重变化多少会改变结论"；
- 每个结论都有数字与脚本可复现。

**先读**：`backend/scripts/build_running_dataset.py`（`W` 与子分公式）
**前置**：无
**预计**：2–3 人日

---

### 卡片 4：骑行（慢骑）模式扩展

**目标**：同一套路网，给出骑行适宜性，与跑步形成对照。

**具体任务**
1. 调整权重：坡度容忍度更高但更敏感、避开主干道权重更大、路面类型更重要；
2. 加入"坡度 > 6% 显著扣分""有专用自行车道加分"两条规则（`fclass == cycleway`）；
3. 重新计算骑行评分，输出对比图（同一路段跑步分 vs 骑行分）；
4. 生成 1–2 条示例骑行环线。

**交付物**：`segment_cycling.csv` + 对比图 + 一段说明

**验收**
- 骑行分在陡坡段明显低于跑步分（如珞珈山、桥头引道）；
- 专用道段两种模式都高，但骑行更高。

**先读**：`build_running_dataset.py`、`docs/数据字典-跑步数据集.md`
**前置**：无（数据齐全，`cycleway` 415 km 已在路网里）
**预计**：2–3 人日

---

### 卡片 5：环线算法改进

**目标**：让环线更像"人设计出来的环线"，而不是绕街区。

**具体任务**
1. 加入转弯角约束（连续 >90° 折返扣分），减少锯齿；
2. 解决 3 km 档候选过少（放宽折点带、允许不同折点数量）；
3. 惩罚"同一路口重复经过"（不只是重复边）；
4. 支持"再来一批"（换方位种子）；
5. 输出算法对比：改进前后 3 个起点的形状与分数。

**交付物**：改进代码 + 对比图 + 指标表（平均转弯数、重复路口数）

**验收**
- 3 km 档每个起点至少 3 条候选；
- 平均转弯次数下降 ≥20%；
- 环线仍闭合，长度误差 <15%。

**先读**：`backend/app/running.py`（`generate_loops` 全流程）
**前置**：无
**预计**：3–4 人日（难度最高，建议给算法基础好的人）

---

### 卡片 6：工程化与可复现

**目标**：让任何人（包括答辩现场）能在 10 分钟内跑出结果。

**具体任务**
1. 一键脚本 `run_all.ps1`：数据检查 → 计算 → 出图；
2. 单元测试：坡度/树冠/评分/环线的关键不变量（pytest）；
3. 生成 `data/raw-inputs.sha256` 的校验脚本，缺数据时给出明确提示；
4. 依赖锁定（`requirements.txt` 版本核对）；
5. 写 `docs/环境与复现.md`：从零到出图，含常见报错。

**交付物**：测试用例（≥10 个）+ 一键脚本 + 复现文档

**验收**
- 删掉 `data/processed/running/` 后，一条命令能重建；
- 缺 `data/raw/worldcover/` 时报错信息明确指出去哪下载。

**先读**：`AGENTS.md` 全部、`backend/scripts/*.py`
**前置**：无
**预计**：2–3 人日

## 三、认领与协作约定

### 3.1 认领方式

每人回复：**第一志愿 + 备选 + 每周可投入时间**。组长按下表平衡：

| 项 | 难度 | 依赖 | 适合 |
|---|---|---|---|
| 1 前端 | 中 | 与 2 有接口约定 | 会 Vue / 想学前端 |
| 2 接口 | 中 | 无 | 会 Python / 后端 |
| 3 验证 | 中高 | 无 | 想主答辩、逻辑强 |
| 4 骑行 | 中 | 无 | 对指标设计感兴趣 |
| 5 环线 | 高 | 无 | 算法基础好 |
| 6 工程化 | 中 | 无 | 细心、愿意写测试 |

### 3.2 分支与提交

```text
main                只收合并，由组长合
feat/frontend-xxx   卡片 1
feat/api-xxx        卡片 2
...
```

提交信息：`feat(frontend): 接入百度底图`、`fix(api): 修复 bbox 越界`。
**不要直接改别人的模块**；需要改公共代码（`running.py`、`build_running_dataset.py`）先提 issue。

### 3.3 完成定义（DoD）

一项工作算完成，必须同时满足：

- [ ] 有代码 / 文档 / 图，且别人能按说明跑出来；
- [ ] 有验收标准里的数据或截图作为证据；
- [ ] 在 `docs/开发进展-慢跑适宜性与环线.md` 里补三行"我做了什么"；
- [ ] 提交信息能追溯到人。

### 3.4 时间表（建议）

| 周 | 内容 |
|---|---|
| 第 1 周 | 卡片 2、6 先起（接口与工程底座），1 并行搭页面骨架 |
