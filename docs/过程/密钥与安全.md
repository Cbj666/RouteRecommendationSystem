# 密钥与安全：Agent 如何拿到高德 Key 而不把 Key 弄丢

> 面向：接手本仓库的 AI Agent（以及人）。
> 本文只讲一件事——**怎么在不泄露的前提下，让脚本用上高德/百度的 Key**。
> 代码实现：`backend/app/secrets.py`；模板：根目录 `.env.example`。

---

## 0. 一句话规则

**环境变量优先，其次项目根 `.env`；值只在内存里用，永远不打印、不写日志、不进代码、不进前端。**

一条命令自检（只输出掩码，不输出值）：

```powershell
.\.venv\Scripts\python.exe -m app.secrets check
```

```
密钥就绪情况（只显示掩码，不显示值）：
  GAODE_KEY        [文件]         已设置（32 位，末 4 位 …803e)
  BAIDU_SERVER_AK  [文件]         已设置（32 位，末 4 位 …0F7S)
  TIANDITU_KEY     [文件]         已设置（32 位，末 4 位 …3dc0)
  AQICN_TOKEN      [文件]         已设置（40 位，末 4 位 …6753)
```

全部就绪返回码 `0`，缺任何一个返回 `1`，便于在 CI 或脚本里判断。

## 1. 有哪些密钥、谁在用

| 规范名 | 可接受的变量名 | 用途 | 必需性 | 消耗配额 |
|---|---|---|---|---|
| `GAODE_KEY` | `AMAP_WEB_KEY` / `GAODE_KEY` / `AMAP_KEY` | 场馆抓取（`fetch_amap_sport_poi.py`）、公厕抓取（`fetch_amap_toilet_poi.py`）、线路试点（`fetch_amap_line_pilot.py`）、在线地点搜索（`/api/places/search`，`app/amap.py`） | **必需** | `place/*` 5,000 次/日、3 QPS |
| `BAIDU_SERVER_AK` | `BAIDU_SERVER_AK` / `BAIDU_AK` | `baidu_place.py`（老线路/站点核验） | 可选 | 免费额度小 |
| `TIANDITU_KEY` | `TIANDITU_KEY` | 备用底图 | 可选 | — |
| `AQICN_TOKEN` | `AQICN_TOKEN` | `fetch_air_quality.py` 站点空气质量（现用 CHAP 栅格，已非必需） | 可选 | 免费限速 |

三个高德名字是同一把 Key 的不同叫法，按 `AMAP_WEB_KEY` → `GAODE_KEY` → `AMAP_KEY` 顺序取第一个非空的。
仓库根 `.env` 里现在写的是 `GAODE_KEY`；部署环境里更推荐语义明确的 `AMAP_WEB_KEY`。

**Key 是组里共用的**：6 个人 + 若干 Agent 对着同一把 Key 跑，最容易撞 3 QPS 限制。
抓取脚本请串行跑，不要并发；已经有缓存的目录不要为了"刷新一下"重跑。

## 2. 唯一的读取规则

```
环境变量  >  .env（项目根）  >  .env.txt（项目根，历史遗留）
```

实现：`backend/app/secrets.py`。所有脚本都应通过它取密钥，**不要自己写正则去读 `.env`**。

```python
from app.secrets import get, require, source_of, mask, redact

key = require("AMAP_WEB_KEY", "GAODE_KEY", "AMAP_KEY")   # 没有就抛 SecretMissing
key = get("AMAP_WEB_KEY", "GAODE_KEY", default="")        # 没有就返回 ""
src, name = source_of("AMAP_WEB_KEY", "GAODE_KEY")        # ("环境变量"|"文件"|"未配置", 命中的名字)
print(mask(key))                                          # 已设置（32 位，末 4 位 …803e)
safe = redact(url)                                        # 把 URL 里的 key=... 换成 key=***
```

之所以让**环境变量优先**：临时会话、CI、别人的机器可以覆盖仓库里的 `.env`，
而不用去改动那个文件；也方便"这次换一把 Key 试试"而不留痕迹。

改 `.env` 后**必须重启**进程才生效（读取结果有 `lru_cache`）；改环境变量则新开进程即可。

## 3. Agent 怎么把变量交给脚本

### 方式 A：只作用于一条命令（推荐，最干净）

PowerShell 里先赋值再调用，变量只存在于这一个进程：

```powershell
$env:AMAP_WEB_KEY = '你的Key'; .\.venv\Scripts\python.exe backend\scripts\fetch_amap_sport_poi.py --dry-run
```

注意：**不要把含 Key 的赋值写进 `.ps1` 脚本、批处理、CI 配置文件、笔记**，
那些文件会入库。用完在同一个会话里清掉：

```powershell
Remove-Item Env:\AMAP_WEB_KEY
```

### 方式 B：本次会话全程可用

```powershell
$env:GAODE_KEY = '你的Key'
.\.venv\Scripts\python.exe -m app.secrets check
```

### 方式 C：写进项目根 `.env`（默认做法，适合长期开发）

```powershell
Copy-Item .env.example .env      # 首次
notepad .env                     # 填 AMAP_WEB_KEY=...
```

`.env` 已在 `.gitignore` 里（实测 `git ls-files` 无任何 `.env`），不会入库。
**不要**把 `.env` 复制到别处、改名成 `env.txt` 再提交、或粘进聊天/Issue/PR。

## 4. Agent 硬性禁令

| # | 禁止 | 原因 |
|---|---|---|
| 1 | `print(key)`、`Write-Host $key`、`echo`、写日志 | 终端输出会进会话记录/截图/CI 日志 |
| 2 | 在 `except` 里 `f"...key={key}"` | 异常字符串会到处冒泡；只报变量名 |
| 3 | 把 Key 写进 `.py`、`.md`、`.json`、`.ipynb`、注释 | 一旦提交，历史里永久留存 |
| 4 | 给变量加 `VITE_` 前缀放前端 | Vite 会把 `VITE_*` 打包进浏览器产物 |
| 5 | 让前端直接调高德/百度（URL 带 Key） | 同上；本项目 Key 只在服务端，见 `app/amap.py` |
| 6 | 把含 `key=` 的 URL 原样写进日志/GeoJSON/错误信息 | 用 `redact()` 处理 |
| 7 | 把 `.env` 内容贴进对话、Issue、README、答辩 PPT | 截图与聊天记录同样会外流 |
| 8 | 用 `git add -f .env`、或用 `--no-verify` 绕过 | 已发生泄露要走第 8 节流程 |
| 9 | 把 Key 写进测试用例的期望值 | 测试文件入库；用 `monkeypatch.setenv` |
| 10 | 在 Agent 的 prompt / 任务描述里附带 Key | 对话上下文可能被记录、被别的模型看到 |

测试里需要 Key 时的正确做法（见 `tests/test_amap.py`）：

```python
monkeypatch.setenv("GAODE_KEY", "test-key")   # 假值，不是真 Key
```

## 6. 前端的一条边界

前端**不持有任何地图厂商的 Key**（高德 / 百度 / 天地图均不例外），也不加载任何第三方地图 JS。
地点搜索只走 `api/client.ts` 的 `searchPlaces` → `GET /api/places/search?q=...`，
由后端 `app/amap.py` 用服务端 Key 转发，前端拿到的只有地点名和 WGS84 坐标。
底图是构建期 `public/geo` 的静态 SVG 图层，不需要 Key。

`frontend/app/.env.example` 只剩一个变量，不含密钥：

| 变量 | 含义 |
|---|---|
| `VITE_USE_MOCK` | `1` 用本地假数据，`0` 打真实 `/api/*` |

**不要再新增 `VITE_BAIDU_AK` 之类的浏览器端 Key**：它会随构建产物下发到浏览器，
既泄露密钥，也绕过后端的坐标转换与配额控制。若确实需要第三方底图，由后端代理瓦片。

## 7. 常见报错对照

| 现象 | 含义 | 处理 |
|---|---|---|
| `SecretMissing: 缺少密钥 GAODE_KEY ...` | 环境变量与 `.env` 都没有 | 按第 3 节任选一种方式注入；确认 `.env` 在**项目根**而不是 `backend/` |
| `INVALID_USER_KEY` / `10001` | Key 错、被删、或用了别家平台的 Key | 控制台确认「Web服务」类型；`app/secrets check` 看末 4 位是否对得上 |
| `USERKEY_PLAT_NOMATCH` / `10009` | 用浏览器端 Key 调服务端接口 | 换「Web服务」Key |
| `DAILY_QUERY_OVER_LIMIT` / `10003` | 当日配额用完 | 第二天再跑；已有缓存不要重抓 |
| `CUQPS_HAS_EXCEEDED_THE_LIMIT` | 超过 3 QPS | 串行 + `SLEEP_S ≥ 0.45`，失败退避；**失败响应不要写缓存** |
| 地点搜索 503 | 服务端没配 Key | `.env` 或环境变量补 `GAODE_KEY`，重启 uvicorn |
| 抓取脚本"什么都没抓到"但退出码 0 | 缓存里有旧的失败响应 | 删掉对应 `data/cache/amap_*/` 下的该条再跑 |

## 8. 万一泄露了

1. **先轮换**：高德控制台删除旧 Key、新建一把，更新 `.env` 与部署环境变量；百度同理。
   轮换比追查更划算——`place/*` 的日配额被刷完，全组当天就没法干活。
2. **查入库历史**：`git log -S '<Key的前 8 位>' --oneline --all`；
   命中则用 `git filter-repo` 清理并强推，同时通知所有组员重新 clone（旧的本地仓库仍留着）。
3. **清外围**：删掉含 Key 的日志、截图、聊天记录、临时脚本、CI 产物。
4. **复盘**：把这次的路径补进第 4 节禁令表，避免下一个人再犯。

## 10. 新增一把密钥时

1. 在 `backend/app/secrets.py` 的 `KNOWN_KEYS` 里加一行（规范名 + 候选别名）；
2. 在根 `.env.example` 加同名条目与注释（申请地址、用途），**值留空**；
3. 本文第 1 节的表加一行；
4. 调用方写 `require(...)`，不要自建读取逻辑；
5. 跑第 9 节四条命令。
