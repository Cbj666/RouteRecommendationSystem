## 2. 页面范围

### 2.1 三个 Tab（顶栏文案照抄，不可改写）

| Tab | 内容 | 优先级 |
|---|---|---|
| **适宜性地图** | 全城/片区底图按 `score` 上色 + 图例 + 点击路段看六维明细 | P0（可先做只读版） |
| **环线推荐** | PPT 第 6 页那张图：左控制栏 + 地图 + 右结果栏 | **P0（核心交付）** |
| **起点对比** | 2–3 个起点并排比较分数/距离/绿化 | P2（时间不够就保留 Tab 并显示「即将上线」空状态，不阻塞验收） |

### 2.2 环线推荐页交互清单

1. 起点卡：显示名称 + WGS84 坐标（默认「武汉大学 · 八一路珞珈山 / 114.3547, 30.5342」）；
2. 地图点击选起点：BD-09 → WGS84 后回填；`origin_snap_m > 100` 时提示「起点已吸附到最近路段」；
3. 搜索框：有 AK 用 BMapGL `LocalSearch`；无 AK 用 3–5 个内置起点（武大 / 东湖 / 江滩 / 磨山 / 沙湖）；
4. 路线模式：`环线` / `单行线 A→B`（**依赖后端新增 `mode`，见 G1**；未落地前置灰并注明）；
5. 目标距离：3 / 5 / 10 km → `target_m`；
6. 偏好四开关：`尽量绿荫 / 滨水`→`green`、`避开机动车主干道`→`safe`、`尽量平坦`→`flat`、`洗手间 / 补给点`→**图层开关（不是路径权重）**，见 G4；
7. 主按钮「生成路线」：请求中禁用 + 进度文案；错误/空结果有明确出口；
8. 结果栏：大分数 + 徽标 + 六宫格 + 三条子分条 + 权重句；
9. 候选切换：`环线 · 第 n 条　回到起点`，支持上一/下一条（API 已返回多条）；
10. 图例：五档色带 + 刻度 30/50/70/85 + 环线示意 +「推荐环线 x.xx km」；
11. 页脚：数据来源整行；
12. 四态：空（未生成）、加载（骨架/按钮态）、失败（可重试，区分 4xx/5xx）、无结果（`features: []` + `message`）。

## 3. 技术方案与关键决策

### 3.1 渲染：`MapAdapter` 抽象 + **SVG 优先、BMapGL 二期**

```ts
interface MapAdapter {
  mount(el: HTMLElement): Promise<void>
  setOrigin(lng: number, lat: number): void
  drawSegments(fc: SegmentCollection): void
  drawLoops(fc: LoopCollection, active: number): void
  fitToLoop(feature: LoopFeature): void
  on(event: 'click', cb: (lng: number, lat: number) => void): void
  destroy(): void
}
```

- `SvgAdapter`：照 `frontend/reference/index.html` 的投影/色阶/线宽/绘制顺序搬进 Vue。**零依赖、无 AK、与 PPT 像素级一致**，作为保底交付；
- `BaiduAdapter`：BMapGL + Canvas 叠加层。8,005 段一次性转 BD-09，`moveend/zoomend` 重绘；不要把 8k 条做成 8k 个 `Polyline`；
- 选 SVG 优先的理由：① AK 申请不可控；② reference 是验收真源，SVG 能保证「对得上」；③ BMapGL 的瓦片底图会改变整体明暗，需要额外压暗/调透明才能贴近 PPT。**若组长要求必须真地图，则把 BaiduAdapter 提到 M1。**

### 3.2 底图资产：复制进 `public/geo/`，不进 git

- **已实现** `frontend/app/scripts/sync-geo.mjs`（Node 内置 `fs`，无新依赖），从 `data/output/running/v1/web/` 复制：
  `segments_city.geojson`、`segments_arterial.geojson`、`water_green.geojson`（`segments_all` 默认不复制，需要时加进 `FILES`）；
- `package.json` 已加 `"sync:geo"`、`"predev"`、`"prebuild"`；实测 dev/build 都会自动同步，`dist/geo/` 已带三份文件；
- `.gitignore` 增加 `frontend/app/public/geo/`（数据已在 `data/` 入库，避免重复 11 MB）；
- 视野策略：默认 `segments_city`；缩到城市级换 `segments_arterial`；`segments_all` 仅按需加载。

### 3.3 数据源划分（写进 D2 文档）

| 用途 | 来源 | 备注 |
|---|---|---|
| 底图路网 | **静态** `/geo/segments_city.geojson` | 不走 `/api/segments`，避免每次 0.6 s 全表扫描 |
| 水/绿 | 静态 `/geo/water_green.geojson` | 可选图层 |
| 环线 | `POST /api/loops`，mock 时按 `(起点, target_m)` 选 4 份快照 | — |
| 路段点击详情 | `GET /api/segments`（小 bbox），mock 用 `segments.json` | `truncated` 要提示 |
| 设施/厕所补给 | `GET /api/facilities`，mock 用 `facilities.json` | `kinds` 未实现，见 G4 |
| 权重/口径/统计 | `GET /api/meta` | 图例脚注、权重句 |
| 健康检查 | `GET /health` | 启动时探测，失败降级 mock |

### 3.4 坐标系

- 后端与静态 GeoJSON 全为 **WGS84**；BMapGL 只认 **BD-09**（直接用会整体偏几百米）；
- `src/lib/coord.ts`：`wgs84ToGcj02 / gcj02ToBd09 / bd09ToGcj02 / gcj02ToWgs84`；
- **只在 `BaiduAdapter` 边界转换一次**（design-guidelines 的通用约束），业务层永远 WGS84；
- 往返测试误差 < 5e-6 度（约 0.5 m）。

### 3.5 状态管理

- 不引 Pinia：页面单实例、状态少，`src/stores/planner.ts` 用 `reactive` + 显式 actions 即可，少一个依赖；
- 状态字段：`origin / originName / mode / targetM / prefs / loops / activeIndex / loading / error / tab / showWater / showFacilities / segmentDetail`；
- 请求竞态用 `AbortController` + 递增 `requestId`，只接受最后一次响应。

### 3.6 请求层（在现有 `client.ts` 上扩展，不重写）

- `fetchLoops` 增加 `signal`、15 s 超时；
- mock 路由：按 `target_m`（3000/5000/10000）与起点远近选 `loops_*`，找不到就用 `loops.json`；
- 错误归一化：`422`（pydantic 数组）、`500`、`503`、网络错误 → `{kind, message, retryable}`，供 UI 映射；
- 结果缓存：同一 `(lng, lat, target_m, prefs)` 5 分钟内复用（`Map`），减少重复等待。

### 3.7 布局与响应式

- 桌面：固定 **1600×1000** 画布，外层 `transform: scale(min(100vw/1600, 100vh/1000))`，`transform-origin: top left` 并居中；**1440×900 恰好 0.9 倍，无留白**；
- `≤ 900px`：单列堆叠（顶栏 → 地图 4:3 → 左控制 → 右结果），左右栏变卡片，**不允许横向滚动**；
- 圆角一律 0；数字 `tabular-nums`；`prefers-reduced-motion` 下关闭过渡。

## 4. API 接口文档：现状审计与缺口

### 4.1 已实现端点（v1.0 实际行为）

| 端点 | 参数 | 返回 | 前端用途 | 实测 |
|---|---|---|---|---|
| `GET /health` | — | `status/nodes/edges/graph_loaded_at` | 启动探测、页脚状态 | 立即 |
| `GET /api/meta` | — | `dataset/weights/score_stats/notes/speed_mps` | 图例脚注、权重句 | 立即 |
| `GET /api/segments` | bbox + `limit`(1–60000, 默认 20000) | FeatureCollection，属性 **11 个**（`osm_id,fclass,name,length_m,score,grade,s_safety,s_green,s_slope,s_cross,s_fac`）+ `truncated` | 点击路段详情 | 约 0.6 s |
| `GET /api/facilities` | bbox + `kinds`(sport/support/all) | Point FeatureCollection，属性仅 `name/type` | 设施图层 | 立即；**`kinds` 被忽略** |
| `POST /api/loops` | `lng/lat` 必填；`target_m`(1000–20000, 默认 5000)；`prefs`；`max_candidates`(2–16, 默认 8) | FeatureCollection；属性 9 个：`rank,length_m,minutes,score,tree_share,slope_mean_pct,facility_m,origin_snap_m,sub` | 路线 + 结果栏 | 5 km 约 1.3 s / 6 条 |
| `GET /docs` | — | Swagger/OpenAPI | 后端自测 | — |

细节：`POST /api/loops` 无解时返回 `{"type":"FeatureCollection","features":[],"message":"…"}`（**HTTP 200，不是错误**）；`sub` 只有 `s_safety/s_green/s_slope` 三个键；`score` 在 loops 与 segments 中是**两种口径**。

> 顺手修正：`types.ts` 注释写 `/api/segments` 12 个属性，实际 `api.py` 的 `keep` 列表是 11 个；D2 文档以 `api.py` 为准。

### 4.2 缺口矩阵

| 编号 | 前端需要 | 现状 | 影响 | 建议方案 |
|---|---|---|---|---|
| **G1** | 路线模式 `环线 / 单行线 A→B` | 算法层 `one_way()` 只在 `build/demo_routes.py:135`；API 无 `mode` | 左栏模式切换无法真正生效 | 后端在 `LoopRequest` 加 `mode:"loop"\|"oneway"`，oneway 额外返回 `destination:{lng,lat}` 与 `closed:false`；前端按 `mode` 改文案与结果字段 |
| **G2** | 点击路段看六维 + 原始指标 | `/api/segments` 无 `s_air`、无 `slope_mean_pct/tree_share/d_main_m/cross_200m/d_fac_m/no2/pm25`，且无单段端点 | 「为什么这段分低」讲不清 | 方案 A：给 segments 加 7 个字段；方案 B：新增 `GET /api/segments/{osm_id}`（推荐，按需取） |
| **G3** | 结果栏徽标「很适宜」 | loops 无 `grade`；loops 的 `score` 与 segments 分档不同源 | 徽标只能前端硬编码阈值，口径存疑 | 后端 loops 返回 `grade` + `score_kind:"preference"`；或在 `/api/meta` 给两套分档 |
| **G4** | 第 4 开关 + 设施图层 | `kinds` 参数被忽略；仅高德场馆；无 `kind` 属性区分 sport/support | 「洗手间/补给点」开关无效 | 后端实现 `sport\|support\|all` 并回 `kind`（support 可合并 OSM 公园/厕所/便利店）；前端把它做成**图层开关**，不参与路径权重 |
| **G5** | 目标距离最多 10 km | 接口上限 20 km（算法支持 42 km） | 当前无阻塞 | 暂不改；D2 写明上限与理由 |
| **G6** | 起点搜索/地理编码 | 无端点 | 搜索框不可用（无 AK 时） | 前端 BMapGL `LocalSearch`（AK）；无 AK 用内置 5 个预设起点 + 地图点击 |
| **G7** | 统一错误提示 | 422（pydantic 数组）/400/500/503 混杂，无 `code` | 无法区分「参数错」「数据没生成」「算法失败」 | 后端统一 `{code,message,hint}`（`INVALID_PARAM/GRAPH_NOT_READY/NO_LOOP_FOUND/INTERNAL`）；前端先做兼容适配 |
| **G8** | 静态底图交付 | `data/output/...` 不在 Vite root | 构建后底图 404 | `sync-geo.mjs` 复制到 `public/geo/`；D2 写明部署时必须带这三份文件 |

补充（写进 D2 即可，不必改后端）：

- `/api/segments` 的 `truncated` 语义是 `len >= limit`，恰好等于 limit 也会为 true；
- loops 的 `minutes` 不含红绿灯等待；
- `origin_snap_m > 100` 需要 UI 提示；
- 无鉴权、无限流、CORS `*`，仅课程演示可用；
- 坐标一律 WGS84，前端只在百度适配器里转 BD-09。
