### 2.4 残留耦合

耦合度评估：**低—中**。两条轻量契约：

1. **DOM 契约**：`HotspotPage` 通过 `.map-frame`、`.map-host svg`、`.map-controls`

   重命名这些类名或改地图 DOM 层级时需同步修改。
2. **视图绑定**：`planner.ts` 的 `HOTSPOT_VIEW`（`113.6928, 30.006` –
   `115.076, 31.338`）必须与网格数据 bbox 一致；重建网格后若范围变化，
   同步 `HOTSPOT_VIEW` 与 `sync-geo.mjs` 里的复制源。

`HotspotOverlay` 依赖现有 `lib/projection.ts`、`lib/color.ts` 与 `HotspotCell` 字段，
均通过公开接口/类型使用。

## 三、数据说明

### 3.1 离线脚本输入与口径

`backend/scripts/build_hotspot_grid.py`：

- 输入：`data/processed/running/v1/segments.gpkg`（图层 `segments`，91,203 段），
  只取 `in_boundary=True` 的路段（64,788 段 / 27,295.4 km）；
- 网格：`CELL_LNG = 0.0104`、`CELL_LAT = 0.009`（1 km 量级），按路段中点归格；
- 聚合：以 `length_m` 为权重，对 `score` 与六维 `s_*` 做长度加权平均，
  输出 `nSeg` / `lenM` / `score` / `subs`；
- 分档：v2 口径 `[35, 50, 65, 80]` → 差 / 一般 / 较好 / 好 / 很好；
- 热点：`isHotspot = score >= 65 and lenM >= 1000`；
- 排名：只有 `lenM >= 1000` 的格子参与 `rank`（从 1 起），样本不足 1 km 的 `rank = 0`，
  前端排序时放最后、详情显示「样本不足 1 km」；
- 命名：优先用休闲旅游面（公园/湖/绿道/景区/山/江滩等）、交通设施点、
  休闲旅游点、场馆 CSV 名称做锚点，按「距离 + 类型惩罚」取最近；
  锚点超过 1.2 km 时补八方位后缀；银行/超市/公厕/停车场等不入锚点。

产物：

```text
data/output/running/v1/hotspot/grid.json      # 前端 payload，约 0.6 MB
data/output/running/v1/hotspot/grid.geojson # 供 GIS 检查，约 0.7 MB
```

本次结果：**1,853 格 / 133 个热点 / 均分 51.4 / 最高 82.8 / rank0 共 115 格**，
bbox `[113.6928, 30.006, 115.0864, 31.338]`。

## 五、已知限制

1. **尺度是 2 km**：任务书设想的 500 m 全市网格未做；城市级视野下 1 km 太碎，2 km 的色块更连贯、样本也更足，后续可做「全市 2 km / 片区 1 km」切换。
2. **热点判定是阈值规则**：`score >= 65 且 lenM >= 1000`，不是 Gi* 等空间统计；
   答辩时表述为「高分路段聚集的网格」，不要称为统计显著热点。
3. **命名是启发式**：锚点就近 + 方位后缀，个别格名可能偏粗（如「集贤北」）；
   需要更准可改用人工地名表或道路名。
4. **渲染是全量 SVG**：按档合并 path 后是 ~7 条路径，性能足够；
   若将来上 500 m（数万格）需视野裁剪或 Canvas/矢量瓦片。
5. **前端不读 `data/`**：静态兜底文件由 `sync-geo.mjs` 复制、不入库；
   换机器时先跑同步脚本。
