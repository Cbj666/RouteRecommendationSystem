### 2.4 残留耦合

耦合度评估：**低—中**。主要残留是两条轻量契约：

1. **DOM 契约**：`HotspotPage` 通过 `.map-frame`、`.map-host svg`、
   `.map-controls` 找到原地图节点，并用 `MutationObserver` 监听 SVG
   `viewBox`，让网格跟随地图缩放/拖动。它没有访问 `SvgAdapter` 的私有方法。
   如果以后重命名这些类名或改变地图 DOM 层级，需要同步修改
   `HotspotPage.vue`。
2. **视图扩展点**：`planner.ts` 的 `HOTSPOT_VIEW` 固定为
   `114.24–114.50, 30.45–30.63`。接真实数据或改变网格范围时，
   同步调整这个 bbox。

`HotspotOverlay` 依赖现有的 `lib/projection.ts`、`lib/color.ts`
和 `HotspotCell` 字段；这些都通过公开接口/新类型使用。

## 三、示例数据说明

当前数据在 `frontend/app/src/mocks/hotspot.ts`：

- 范围：`114.24–114.50, 30.45–30.63`（都市区示意，不是全市）；
- 网格：1 km × 1 km，25 列 × 20 行 = 500 格；

- 热点：示例中按 `score >= 66` 标记，当前只有少量格；
- 选中格默认取排名第一的示例格。

### 3.1 真实数据目标

任务书约定的真实产物是：

```text
data/output/running/v1/hotspot/grid_500m.geojson
data/output/running/v1/hotspot/grid_1000m.geojson
data/output/running/v1/hotspot/hotspots.geojson
data/output/running/v1/hotspot/top20.json
data/output/running/v1/hotspot/summary.json
```

前端字段映射建议：

| UI 字段 | 真实数据字段 |
|---|---|
| `id` | `cell_id` |
| `name` | `name` 或“区 + 地名” |
| `cluster` | `cluster_name` |
| `lng` / `lat` | 格心坐标 |
| `widthLng` / `heightLat` | 由网格多边形计算或保留格宽/格高 |
| `score` | `score` |
| `grade` | `grade` |
| `rank` | `rank` |
| `nSeg` | `n_seg` |
| `lenM` | `len_m` |
| `isHotspot` | `is_hotspot` |
| `subs.s_*` | `s_safety` / `s_green` / `s_slope` / `s_cross` / `s_fac` / `s_air` |

如果真实数据使用任意多边形而不是矩形，`HotspotOverlay` 需要把
`cellPath()` 改成读取 `geometry`，并把点击命中从矩形判断改成
点是否在多边形内。`HotspotPage` 的选中逻辑和榜单不需要改。

## 五、已知限制

1. **数据是示例，不是分析结论**：没有跑 Gi*、网格聚合或真实路段评分；
   不能把当前的 70 分、3 个热点格写进答辩结论。
2. **尺度是 1 km 都市区，不是任务书最终的 500 m 全市网格**：
   500 m 在全市视野下会非常密，后续应做“全市 1 km / 片区 500 m”切换，
   或按当前视野裁剪。
3. **网格只有示例字段**：地名、热点簇名、Top20 的真实道路名尚未接；
   真实数据需要生成稳定的 `cell_id` 和可读名称。
4. **前端覆盖层是 SVG 全量渲染**：当前 500 格很轻；真实 500 m 网格若有
   1 万格以上，需要视野裁剪、分级加载或 Canvas/矢量瓦片优化。
5. **没有后端/API 改动**：热点页当前完全静态；如果以后要按 bbox 查询，
   再新增接口，不要在前端直接读 `data/`。
