# 接口契约 v1（前后端唯一依据）

> 维护人：组长（签字后生效） · 最后更新：2026-11-04
> 机器可读版：后端启动后访问 `http://127.0.0.1:8000/docs`（FastAPI 自动生成的 OpenAPI）
> 本文件改动必须同步通知前端组与后端组；**字段增删只能在「变更记录」里留痕后改**。

---

## 0. 一句话

前端只通过 **5 个 HTTP 接口** 拿数据，全部 **JSON over HTTP/1.1**；没有 gRPC、没有 WebSocket、没有鉴权。
坐标一律 **WGS84（EPSG:4326）**，`[经度, 纬度]` 顺序，BMapGL 需要时由前端转 BD-09。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 开发：`http://127.0.0.1:8000`（前端走 vite 代理，写相对路径 `/api/...`） |
| 编码 | UTF-8，`Content-Type: application/json` |
| 坐标系 | WGS84，经纬度，`[lng, lat]` |
| 几何 | GeoJSON（`Feature` / `FeatureCollection`），坐标为 `[lng, lat]` 数组 |
| 时间 | 无业务时间字段；`graph_loaded_at` 是服务器 unix 时间戳（秒） |
| 成功状态码 | 200 |
| 参数校验失败 | **422**，body 为 FastAPI 标准结构（见 §2.6） |
| 数据未生成 | 503（`/api/segments`、`/api/facilities` 读不到文件时） |
| 算法异常 | 500 |
| 截断 | 只出现在 `/api/segments`，用 `truncated: true` 标记 |

**性能基线（本机实测）**：`/health` 立即返回；`/api/meta` < 10 ms；`/api/segments`（1200 段）约 0.6 s；
`/api/facilities`（216 点）< 0.2 s；`/api/loops`（5 km）约 **1.3 s**，返回 6 条候选。

## 2. 五个端点

### 2.1 `GET /health` — 服务与图状态

用途：前端启动自检、答辩现场确认「图加载好了」。

```bash
curl http://127.0.0.1:8000/health
```

```json
{
  "status": "ok",
  "nodes": 979351,
  "edges": 2075761,
  "graph_loaded_at": 1793792964.23
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 恒为 `"ok"`（失败时接口直接 5xx） |
| `nodes` / `edges` | int | 路网图规模，前台可显示「979,351 节点 / 2,075,761 条边」 |
| `graph_loaded_at` | number | unix 时间戳（秒），进程启动加载图的时刻 |

---

### 2.2 `GET /api/meta` — 权重、分档、数据版本

用途：右栏脚注、图例、关于页；也是「这个分数怎么来的」的公开口径。

```bash
curl http://127.0.0.1:8000/api/meta
```

```json
{
  "dataset": "running/v1",
  "weights": { "safety": 0.25, "green": 0.25, "slope": 0.15,
               "cross": 0.10, "fac": 0.05, "air": 0.15 },
  "score_stats": { "count": 91203.0, "mean": 51.5, "std": 9.4, "min": 17.7,
                   "10%": 38.2, "50%": 52.8, "90%": 62.8, "max": 79.8 },
  "speed_mps": 2.78,
  "notes": ["坡度来自 SRTM 1\"，150 m 高斯平滑后求梯度；城区精度约 ±1 个百分点", "..."]
}
```

| 字段 | 说明 |
|---|---|
| `weights` | 六维权重，**合计 0.95**（沿用上一版口径，所以总分上限是 95） |
| `score_stats` | 全市 91,203 段的分数分布，可直接画「你在哪一档」 |
| `speed_mps` | 步速 2.78 m/s（10 km/h），用于 `minutes` 换算 |
| `notes` | 五个维度的数据口径（答辩时逐条念得出来） |

---

### 2.3 `GET /api/segments` — 评分底图（bbox 内路段）

```bash
curl "http://127.0.0.1:8000/api/segments?min_lng=114.352&min_lat=30.530&max_lng=114.366&max_lat=30.540&limit=1200"
```

| 参数 | 类型 | 必填 | 范围 | 默认 |
|---|---|---|---|---|
| `min_lng` / `min_lat` / `max_lng` / `max_lat` | float | 是 | 市域内 | — |
| `limit` | int | 否 | 1–60000 | 20000 |

返回 `FeatureCollection`，**多一个 `truncated` 字段**（`true` 表示该 bbox 内超过 `limit`，被截断）：

```json
{ "type": "FeatureCollection", "truncated": true,
  "features": [{
    "type": "Feature",
    "properties": {
      "osm_id": 1471868944, "fclass": "footway", "name": "",
      "length_m": 108.7, "score": 65.0, "grade": "较好",
      "s_safety": 95.0, "s_green": 76.2, "s_slope": 85.7,
      "s_cross": 0, "s_fac": 61.7
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3546, 30.5342], [114.3547, 30.5344]] }
  }] }
```

**每要素只有 12 个属性字段**（渲染底图够用）。注意：

- **没有 `s_air` / `no2_ugm3`**（已知缺口，见 §4）；
- `grade` 取值：`差` / `一般` / `较好` / `好` / `很好`；
- 一次别要太多：`limit=60000` 是硬上限，全市 91,203 段必然截断。底图按视口分块请求。

着色建议：`score` 25–70 映射到 RdYlGn（色带见 `docs/过程/design-guidelines.md`）。

### 2.4 `GET /api/facilities` — 设施点

```bash
curl "http://127.0.0.1:8000/api/facilities?min_lng=114.33&min_lat=30.515&max_lng=114.40&max_lat=30.570&kinds=all"
```

| 参数 | 类型 | 必填 | 取值 | 默认 |
|---|---|---|---|---|
| bbox 四个 | float | 是 | — | — |
| `kinds` | string | 否 | `sport` / `support` / `all` | `all` |

```json
{ "type": "FeatureCollection",
  "features": [{ "type": "Feature",
    "properties": { "name": "Benefit Fitness", "type": "体育休闲服务;运动场馆;健身中心" },
    "geometry": { "type": "Point", "coordinates": [114.3518, 30.5640] } }] }
```

- `type` 是高德 **三级分号码**，多标签用 `|` 连接（如 `...;健身中心|购物服务;...`），前端截取最后一级做图例即可；
- **`kinds=support` 还没实现**（现在会静默返回全部）；`kinds` 传非法值也**不报错**，同理会返回全部 —— 这是待改项，见 §4。

### 2.5 `POST /api/loops` — 生成候选环线

```bash
curl -X POST http://127.0.0.1:8000/api/loops \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,
       "prefs":{"green":1.0,"safe":1.0,"flat":0.6},"max_candidates":8}'
```

请求体：

| 字段 | 类型 | 必填 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| `lng` / `lat` | float | 是 | 市域内 | — | 起点（WGS84） |
| `target_m` | int | 否 | **1000–20000** | 5000 | 目标距离；1–42 km 算法侧能跑，但**接口当前上限 20 km** |
| `prefs` | object | 否 | 各 0–1 | 见下 | `{green, safe, flat}`，影响代价函数 |
| `max_candidates` | int | 否 | 2–16 | 8 | 候选条数（越大越慢） |

返回（按 `rank` 升序，**第 1 条是推荐**）：

```json
{ "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": {
      "length_m": 5339.5, "minutes": 32.0, "score": 78.5,
      "tree_share": 0.576, "slope_mean_pct": 3.55, "facility_m": 240.0,
      "origin_snap_m": 0.6,
      "sub": "{\"s_green\": 81.0, \"s_slope\": 64.5, \"s_safety\": 84.3}",
      "rank": 1
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3547, 30.5342], "...共 535 个点"] }
  }] }
```

关键点（**前端最容易踩**）：

- `sub` 是 **JSON 字符串**，要 `JSON.parse(props.sub)` 才能拿到三个子分；只有 `s_safety` / `s_green` / `s_slope` 三项（偏好匹配分，不是六维加权分）；
- `score` 是**偏好匹配分**（0–100），与 `/api/segments` 里的段分数**不同口径**，别混在一起排序；
- `origin_snap_m` 是起点吸附到路网的距离，> 100 m 时建议在 UI 上提示「起点离道路较远」；
- `minutes` 按 2.78 m/s 折算，未考虑红绿灯停留；
- 几何是**闭合环线**（首尾点相同）。

### 2.6 错误结构

FastAPI 默认结构，前端按 `detail[0].msg` 展示即可：

```json
{ "detail": [{ "type": "less_than_equal", "loc": ["query", "limit"],
               "msg": "Input should be less than or equal to 60000",
               "input": "99999", "ctx": { "le": 60000 } }] }
```

| 场景 | 状态码 | `loc` 示例 |
|---|---|---|
| 数值越界（limit / target_m / max_candidates） | 422 | `["query","limit"]`、`["body","target_m"]` |
| 缺必填字段 | 422 | `["body","lng"]` |
| 数据文件缺失 | 503 | — |
| 算法异常 | 500 | — |

**错误码目前不统一**（`/api/segments`、`/api/facilities` 用 503，`/api/loops` 用 500），已在 §4 列为待改项。

## 3. 前端怎么联调

### 3.1 有后端

```powershell
# 1) 起后端（项目根目录）
.\.venv\Scripts\python.exe -m uvicorn app.api:app --app-dir backend --port 8000

# 2) 起前端
cd frontend\app
npm install
npm run dev        # http://127.0.0.1:5173，/api 与 /health 自动代理到 8000
```

### 3.2 没有后端（只写 UI）

`frontend/app/src/mocks/` 里放了**真实响应**，字段与线上完全一致：

| 文件 | 对应接口 | 大小 |
|---|---|---|
| `health.json` | `GET /health` | 0.1 KB |
| `meta.json` | `GET /api/meta` | 0.8 KB |
| `segments.json` | `GET /api/segments`（东湖局部 1200 段） | 970 KB |
| `facilities.json` | `GET /api/facilities`（216 点） | 62 KB |
| `loops.json` | `POST /api/loops`（5 km，6 条候选） | 120 KB |

在 `frontend/app/.env.local` 里写 `VITE_USE_MOCK=1` 即走本地 JSON；`api/client.ts` 已实现切换。

## 4. 已知缺口（谁认领谁改，改完更新本文件）

| # | 问题 | 影响 | 归属 |
|---|---|---|---|
| 1 | `/api/segments` 不含 `s_air`、`no2_ugm3` | 前端画不出空气图层 | 后端组 |
| 2 | `/api/facilities` 的 `kinds=support` 未实现，非法值静默返回全部 | 图例「洗手间/补给点」是假的 | 后端组 |
| 3 | 错误码 500 / 503 不统一 | 前端无法区分「数据没生成」与「算法崩了」 | 后端组 |
| 4 | `/api/loops` 的 `target_m` 上限 20000 | 产品说 1–42 km，接口只到 20 km | 后端组（算法侧已支持，改 `le` 即可） |
| 5 | 无鉴权、无限流、无 CORS 白名单 | 只能本机跑，不能公网部署 | 组长（部署前定） |
| 6 | `minutes` 未含红绿灯停留 | 时间估计偏乐观 | 后端组 |
