# 接口契约 v1.5（前后端唯一依据）

> 维护人：组长（签字后生效） · 最后更新：2026-11-25
> 机器可读版：后端启动后访问 `http://127.0.0.1:8000/docs`（FastAPI 自动生成的 OpenAPI）
> 本文件改动必须同步通知前端组与后端组；**字段增删只能在「变更记录」里留痕后改**。

---

## 0. 一句话

前端只通过 **13 个 HTTP 接口** 拿数据，全部 **JSON over HTTP/1.1**；没有 gRPC、没有 WebSocket、没有鉴权。
坐标一律 **WGS84（EPSG:4326）**，`[经度, 纬度]` 顺序。前端使用静态 SVG 底图，不做坐标系偏移；
不加载任何第三方地图 JS，也不持有地图开发者 Key（地点搜索走 `/api/places/search`）。

**数据归属**：`segments.gpkg`、`water_green.geojson`、`amap_sport_poi.csv`、`amap_toilet_poi.csv` 由后端启动时读入内存，
`hotspot/grid.json`（默认 2 km 网格）由后端按需读取并缓存；前端**不再** `fetch` `data/` 下的任何文件。
Vue 只认 `/api/...`、`/health` 与构建期复制到 `public/geo/` 的静态兜底。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 开发：`http://127.0.0.1:8000`（前端走 vite 代理，写相对路径 `/api/...`） |
| 编码 | UTF-8 |
| 图层响应 | `Content-Type: application/geo+json`（GeoJSON） |
| 普通响应 | `Content-Type: application/json`（health / layers / meta） |
| 坐标系 | WGS84，经纬度，`[lng, lat]` |
| 几何 | GeoJSON（`Feature` / `FeatureCollection`），坐标为 `[lng, lat]` 数组 |
| 压缩 | 请求头带 `Accept-Encoding: gzip` 时，> 1 KB 的响应自动 gzip |
| CORS | 开发期 `Access-Control-Allow-Origin: *`；生产部署前必须收紧 |
| 时间 | 无业务时间字段；`graph_loaded_at` / `datasets_loaded_at` 是服务器 unix 时间戳（秒） |
| 成功状态码 | 200 |
| 参数校验失败 | **422**，body 为 FastAPI 标准结构，或 `{"detail": "中文字符串"}`（bbox / 路线业务校验） |
| 数据未生成 | **503**，`{"detail": "..."}`（某个源文件缺失/损坏） |
| 资源不存在 | **404**（仅 `/api/segments/{osm_id}`） |
| 算法异常 | **500**（`POST /api/routes` 及兼容别名，内部异常只记日志，不回显堆栈） |
| 截断 | 图层接口均带 `truncated: true/false`；`total` 是截断前的数量 |

**bbox 规则（所有图层接口统一）**：

- 四个参数 `min_lng` / `min_lat` / `max_lng` / `max_lat` **要么全给，要么全不给**；
- 全不给时：`/api/segments` 用默认视口 `(114.305, 30.508, 114.405, 30.562)`，
  `/api/water-green`、`/api/pois`、`/api/toilets` 返回全市；
- 只给一部分，或 `min_lng >= max_lng` / `min_lat >= max_lat` → **422**；
- bbox 是 WGS84 经纬度，不是米。

**性能基线（本机实测，2026-11-25，预热后）**：

| 请求 | 耗时 | 原始体积 | gzip 后 |
|---|---:|---:|---:|
| `GET /api/segments`（默认视口，8,425 段，basic） | 约 0.02 s | 约 4.3 MB | 约 0.65 MB |
| `GET /api/water-green`（全市 3,586 面） | 0.57 s | 2.79 MB | 611 KB |
| `GET /api/pois`（默认 4,146 点） | 0.14 s | 2.13 MB | 297 KB |
| `GET /api/toilets`（全市 5,979 点） | 约 0.1 s | 约 2 MB | 约 280 KB |
| `POST /api/routes`（5 km 环线） | 约 0.37 s（8 候选 0.44 s） | 约 63 KB/6 条 | — |
| `POST /api/routes`（5 km 单行线） | 约 0.15 s | 约 40–90 KB/≤8 条 | — |
| `POST /api/routes`（42 km 环线） | 约 0.43 s | 约 60–100 KB | — |
| `POST /api/routes`（首次请求，冷启动后） | 约 0.76 s | — | — |

启动时一次性预热：图（含 KD 树）约 0.2–0.9 s、四个数据集约 0.9 s、水体并集约 0.8 s；
预热后首个路线请求不再有 1–1.6 s 的额外等待（2026-11-24 前：冷 5.1 s、热 2.3 s）。
路线接口没有结果缓存；同一组参数重复请求会重新计算（NFR-06 只保证结果顺序稳定，不保证耗时）。
路线耗时口径：距离场只算到折点带外缘（`limit=0.62×目标`），去程/回程在起点欧氏球内
（半径 0.66×目标）的局部子图上跑，详见 `docs/项目说明书.md` §7.4。

## 3. 端点明细

### 3.1 `GET /health` — 服务与数据状态

用途：前端启动自检、答辩现场确认「图加载好了、数据齐了」。

```bash
curl http://127.0.0.1:8000/health
```

```json
{
  "status": "ok",
  "nodes": 979351,
  "edges": 2075761,
  "graph_loaded_at": 1794919734.83,
  "datasets": {
    "segments": 91203,
    "water_green": 3586,
    "pois": 5137,
    "toilets": 5979
  },
  "datasets_loaded_at": 1794919735.56
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 恒为 `"ok"`（失败时接口直接 5xx） |
| `nodes` / `edges` | int | 路网图规模，前台可显示「979,351 节点 / 2,075,761 条边」 |
| `graph_loaded_at` | number | 图加载完成的 unix 时间戳（秒） |
| `datasets` | object | 四个图层的行数；未加载成功时对应值为 `null` |
| `datasets_loaded_at` | number | 数据集预热完成的 unix 时间戳（秒） |

> 数据集缺失不会阻止服务启动：`/health` 仍返回 200，但对应值为 `null`，
> 该图层的接口会返回 503；启动日志里会打印 `[api] WARNING dataset ...`。

| 字段 | 说明 |
|---|---|
| `available` | `false` 表示源文件缺失；此时该层只有 `endpoint` 与 `error`，不会让整个接口 500 |

### 3.4 `GET /api/segments` — 评分底图（bbox 内路段）

```bash
curl "http://127.0.0.1:8000/api/segments?min_lng=114.352&min_lat=30.530&max_lng=114.366&max_lat=30.540&limit=1200"
```

| 参数 | 类型 | 必填 | 范围 | 默认 |
|---|---|---|---|---|
| `min_lng` / `min_lat` / `max_lng` / `max_lat` | float | 否 | 市域内，四参同给 | `114.305, 30.508, 114.405, 30.562` |
| `limit` | int | 否 | 1–60000 | 20000 |
| `detail` | string | 否 | `basic` / `full` | `basic` |

返回 `FeatureCollection`，顶层多四个字段：

```json
{
  "detail": "basic",
  "total": 8425,
  "truncated": false,
  "bbox": [114.305, 30.508, 114.405, 30.562],
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": { "osm_id": 1471868944, "score": 65.0, "grade": "较好" },
    "geometry": { "type": "LineString",
                  "coordinates": [[114.3546, 30.5342], [114.3547, 30.5344]] }
  }]
}
```

**`detail=basic`：3 个属性字段**（只够画底图；着色用 `score` / `grade`）：

```text
osm_id, score, grade
```

> 2026-11-25 起 basic 从 14 字段砍到 3 字段：`fclass` / `name` / `length_m` / 六维 / 空气
> 只在路段详情里用，改走 `detail=full` 或 `/api/segments/{osm_id}`。
> 前端若要按这些字段二次着色，必须改用 `full`。

**`detail=full`：26 个属性字段**，另含：

```text
fclass, name, length_m, walk_group, in_boundary, slope_mean_pct, elev_gain_m,
tree_share, green_share, d_green_m, d_water_m, d_main_m, d_fac_m, cross_200m,
fac_500m, s_safety, s_green, s_slope, s_cross, s_fac, s_air, no2_ugm3, pm25_ugm3
```

### 性能（v1.5）

`detail=basic` 不再走 geopandas：启动时后台建 **0.01° 网格索引**（`backend/app/segment_tiles.py`），
每段坐标预序列化到 5 位小数、拼成 JSON 片段，响应体连同 gzip 字节一起进 LRU 缓存（最多 96 条），
同一 bbox 的第二次请求基本是内存拷贝：

| 范围 | 改造前 | 改造后（命中缓存） | 传输（gzip） |
|---|---|---|---|
| 路线级 ~1.2 km（约 2.6k 段） | 1.39 MB / 56–122 ms | 0.68 MB / 12–15 ms | 93 KB |
| 区级 ~4 km（约 9.2k 段） | 5.17 MB / 188–212 ms | 2.60 MB / 5–27 ms | 376 KB |
| 全市（约 30k 段） | 17.15 MB / 642 ms | 8.61 MB / 6–18 ms | 1.33 MB |

配套约定：

- 响应带 `ETag`（含 `segments.gpkg` 的 mtime + 大小）与 `Cache-Control: public, max-age=600`；
  带 `If-None-Match` 命中时返回 **304**，前端可据此跳过 `JSON.parse`。
- 响应带 `Content-Encoding: gzip` 与 `Vary: Accept-Encoding`（压缩字节随缓存复用，不再逐次压缩）。
- 索引按**外包框相交**筛选，比几何相交多出极少数「bbox 压到视口、线本身绕开」的边界段
  （实测 ≤0.2%，且都贴着视口边缘，画出来也在视野外）；`total` 可能比几何口径多 1–2。
- `detail=full` 仍是原来的 geopandas 路径（`clip` + `head`），字段与行为不变。

关键点：

- `score` 是路段六维加权分（0–100），**与 `/api/routes` 的偏好匹配分不是同一口径**；
- `grade` 取值：`差` / `一般` / `较好` / `好` / `很好`，分档见 `/api/meta`；
- `d_green_m` / `d_water_m` / `d_main_m` 的 **`null` 表示超出搜索半径**，不是 0；
- `pm25_ugm3` 只展示，不进评分；
- 一次别要太多：`limit=60000` 是硬上限，全市 91,203 段必然截断。底图按视口分块请求，
  或先用 `/api/layers` 的 `bbox` 取全市。
- 默认视口覆盖 PPT 原型那一屏（约 8,425 段）；城市级视野请显式传更大的 bbox。

着色建议：`score` 25–70 映射到 RdYlGn（色带见 `docs/过程/design-guidelines.md`）。

### 3.6 `GET /api/water-green` — 水体 / 绿地底图

```bash
curl "http://127.0.0.1:8000/api/water-green?min_lng=114.30&min_lat=30.50&max_lng=114.42&max_lat=30.58&kind=water&simplify=0.0002"
```

|---|---|---|---|---|
| bbox 四个 | float | 否 | 四参同给 | 全市 |
| `kind` | string | 否 | `water` / `green` / `all` | `all` |
| `simplify` | float | 否 | 0–0.001（度） | `0`（不简化） |
| `limit` | int | 否 | 1–10000 | 10000 |

返回 `FeatureCollection`，顶层多：

```json
{
  "kind": "all",
  "total": 3586,
  "truncated": false,
  "type": "FeatureCollection",
  "features": [{
```

### 3.10 `GET /api/places/search` — 地点搜索（前端搜索框）

用途：把 TopBar 的地点搜索接到高德 Web 服务。**Key 只存在后端**（环境变量

| `q` | str | 是 | 1–64 字符；去空白后不能为空（否则 422） | — |
| `limit` | int | 否 | 1–20 | 8 |


### 3.11 `POST /api/routes` — 生成环线或 A→B 单行线（推荐入口）

```bash
# 环线
curl -X POST http://127.0.0.1:8000/api/routes \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,"mode":"loop",
       "prefs":{"green":1.0,"safe":1.0,"flat":0.6},"max_candidates":8}'

# 单行线 A→B（不指定终点：系统按目标距离自动选终点）
curl -X POST http://127.0.0.1:8000/api/routes \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,"mode":"oneway"}'

# 单行线 A→B（指定终点）
curl -X POST http://127.0.0.1:8000/api/routes \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,"mode":"oneway",
       "end_lng":114.36,"end_lat":30.54}'
```

请求体：

| 字段 | 类型 | 必填 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| `lng` / `lat` | float | 是 | 武汉市数据范围内 | — | 起点（WGS84） |
| `target_m` | float | 否 | **1000–42000** | 5000 | 目标距离；NFR-04 支持 1–42 km |
| `mode` | string | 否 | `loop` / `oneway` | `loop` | 环线 / A→B |
| `prefs` | object | 否 | 各 ≥ 0，总和 > 0 | `{green:1.0, safe:1.0, flat:0.6}` | 只接受 `green` / `safe` / `flat`；未知键 422 |
| `max_candidates` | int | 否 | 2–16 | 8 | 候选条数；指定终点时固定 1 条 |
| `end_lng` / `end_lat` | float | 否 | 数据范围内 | — | 仅 `oneway`；必须同时给或同时省略 |

**起点/终点校验**（422，`detail` 为中文）：

- 经纬度非有限数、超出合法范围 → 422；
- 不在武汉市路网数据 bbox（外扩 0.02°）→ 422；
- 落在水体面内 → 422，提示移到岸边；
- 到最近道路 > **500 m** → 422，并返回实际吸附距离；
- `loop` 传了 `end_lng/end_lat` → 422；
- `oneway` 只给一个终点坐标 → 422；
- `prefs` 含未知键、负值，或全 0 → 422。

返回（`Content-Type: application/geo+json`，按 `rank` 升序，**第 1 条是推荐**）：

```json
{
  "type": "FeatureCollection",
  "dataset": "running/v1",
  "crs": "EPSG:4326",
  "mode": "loop",
  "target_m": 5000.0,
  "count": 6,
  "origin": {
    "lng": 114.3547, "lat": 30.5342, "snap_m": 0.6,
    "snapped_lng": 114.354694, "snapped_lat": 30.534203
  },
  "features": [{
    "type": "Feature",
    "properties": {
      "name": "route", "rank": 1,
      "mode": "loop", "target_m": 5000.0, "target_ok": true,
      "length_m": 5339.5, "length_error_m": 339.5, "length_error_pct": 6.8,
      "minutes": 32.0, "score": 78.5, "pref_score": 78.5,
      "mean_segment_score": 71.2,
      "tree_share": 0.576, "slope_mean_pct": 3.55, "facility_m": 82.0,
      "cross_200m": 1.2, "origin_snap_m": 0.6,
      "sub": "{\"s_green\": 81.0, \"s_slope\": 64.5, \"s_safety\": 84.3}",
      "start_lng": 114.354694, "start_lat": 30.534203,
      "end_lng": 114.354694, "end_lat": 30.534203
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3547, 30.5342], "...共 535 个点"] }
  }]
}
```

关键点（**前端最容易踩**）：

- `sub` 是 **JSON 字符串**，要 `JSON.parse(props.sub)` 才能拿到三个子分；只有
  `s_safety` / `s_green` / `s_slope` 三项（偏好匹配分，不是六维加权分）；
- `score` / `pref_score` 是**偏好匹配分**（0–100），与 `/api/segments` 里的段分数**不同口径**；
- `target_ok` 是布尔值：`0.85 × target_m ≤ length_m ≤ 1.15 × target_m`；
  环线与自动单行线只返回 `target_ok=true` 的候选；**指定终点的 A→B 可能为 false**，
  此时顶层给 `notice`，前端应展示实际距离偏差；
- `origin_snap_m` 是起点吸附到路网的距离，> 100 m 时建议在 UI 上提示「起点离道路较远」；
- `minutes` 按 2.78 m/s 折算，未考虑红绿灯停留；
- 环线几何**闭合**（`start_lng == end_lng && start_lat == end_lat`）；
  单行线首尾不同，`end_lng/end_lat` 是实际终点；
- 没有候选时仍返回 **200**：`features: []`，顶层带
  `reason: "no_candidates"`、`message`、`suggestions`，不是 404；
- 算法内部异常返回 **500**，`detail` 是通用中文提示，不泄露堆栈。

### 3.14 错误结构

**FastAPI 参数校验（422）**：

```json
{ "detail": [{ "type": "less_than_equal", "loc": ["query", "limit"],
               "msg": "Input should be less than or equal to 60000",
               "input": "99999", "ctx": { "le": 60000 } }] }
```

**bbox / 路线业务校验（422）** 的 `detail` 是字符串：

```json
{ "detail": "bbox 四个参数必须同时提供：min_lng / min_lat / max_lng / max_lat" }
{ "detail": "起点位于水体内部，请选择靠近道路的岸边位置" }
{ "detail": "起点距最近道路 784 m，超过 500 m 上限；请把点移到道路附近后重试" }
```

**数据缺失（503）**：

```json
{ "detail": "data/processed/running/v1/segments.gpkg 不存在；请先运行 backend/scripts/build_running_dataset.py" }
```

| 场景 | 状态码 | `detail` 形态 |
|---|---|---|
| 数值越界（limit / target_m / max_candidates / simplify） | 422 | FastAPI 数组 |
| 缺必填字段 | 422 | FastAPI 数组 |
| bbox 只给一部分 / 边界反了 | 422 | 字符串 |
| `kinds=support` | 422 | FastAPI 数组（`literal_error`） |
| 起点/终点在水体、越界、离路网 > 500 m | 422 | 字符串 |
| 未知 prefs / 负权重 / 全 0 | 422 | 字符串 |
| `osm_id` 不存在 | 404 | 字符串 |
| 源文件缺失/损坏 | 503 | 字符串 |
| 路线算法异常 | 500 | 字符串（通用提示） |

前端展示时，`detail` 可能是字符串也可能是数组，建议：

```ts
const detail = body?.detail
const message = Array.isArray(detail) ? detail[0]?.msg : detail
```
