# 接口契约 v1.1（前后端唯一依据）

> 维护人：组长（签字后生效） · 最后更新：2026-11-17
> 机器可读版：后端启动后访问 `http://127.0.0.1:8000/docs`（FastAPI 自动生成的 OpenAPI）
> 本文件改动必须同步通知前端组与后端组；**字段增删只能在「变更记录」里留痕后改**。

---

## 0. 一句话

前端只通过 **9 个 HTTP 接口** 拿数据，全部 **JSON over HTTP/1.1**；没有 gRPC、没有 WebSocket、没有鉴权。
坐标一律 **WGS84（EPSG:4326）**，`[经度, 纬度]` 顺序，BMapGL 需要时由前端转 BD-09。

**数据归属**：`segments.gpkg`、`water_green.geojson`、`amap_sport_poi.csv` 由后端在启动时读入内存，
前端**不再** `fetch` `data/` 下的任何文件。Vue 只认 `/api/...` 与 `/health`。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 开发：`http://127.0.0.1:8000`（前端走 vite 代理，写相对路径 `/api/...`） |
| 编码 | UTF-8 |
| 图层响应 | `Content-Type: application/geo+json`（GeoJSON） |
| 普通响应 | `Content-Type: application/json`（health / layers / meta / loops） |
| 坐标系 | WGS84，经纬度，`[lng, lat]` |
| 几何 | GeoJSON（`Feature` / `FeatureCollection`），坐标为 `[lng, lat]` 数组 |
| 压缩 | 请求头带 `Accept-Encoding: gzip` 时，> 1 KB 的响应自动 gzip |
| CORS | 开发期 `Access-Control-Allow-Origin: *`；生产部署前必须收紧 |
| 时间 | 无业务时间字段；`graph_loaded_at` / `datasets_loaded_at` 是服务器 unix 时间戳（秒） |
| 成功状态码 | 200 |
| 参数校验失败 | **422**，body 为 FastAPI 标准结构，或 `{"detail": "中文字符串"}`（bbox 校验） |
| 数据未生成 | **503**，`{"detail": "..."}`（某个源文件缺失/损坏） |
| 资源不存在 | **404**（仅 `/api/segments/{osm_id}`） |
| 算法异常 | **500**（仅 `/api/loops`） |
| 截断 | 图层接口均带 `truncated: true/false`；`total` 是截断前的数量 |

**bbox 规则（所有图层接口统一）**：

- 四个参数 `min_lng` / `min_lat` / `max_lng` / `max_lat` **要么全给，要么全不给**；
- 全不给时：`/api/segments` 用默认视口 `(114.305, 30.508, 114.405, 30.562)`，
  `/api/water-green`、`/api/pois` 返回全市；
- 只给一部分，或 `min_lng >= max_lng` / `min_lat >= max_lat` → **422**；
- bbox 是 WGS84 经纬度，不是米。

**性能基线（本机实测，2026-11-17，首次请求含预热后）**：

| 请求 | 耗时 | 原始体积 | gzip 后 |
|---|---:|---:|---:|
| `GET /api/segments`（默认视口，8,425 段，basic） | 0.87 s | 4.85 MB | 709 KB |
| `GET /api/water-green`（全市 3,586 面） | 0.57 s | 2.79 MB | 611 KB |
| `GET /api/pois`（默认 4,146 点） | 0.14 s | 2.13 MB | 297 KB |
| `GET /api/layers` | 20 ms | 约 4.4 KB | — |
| `POST /api/loops`（5 km） | 1–3 s | 约 63 KB/6 条 | — |

启动时图与数据各预热一次：图约 0.4 s，三个数据集约 0.9 s；之后请求只做 bbox 过滤与序列化。

| # | 方法 | 路径 | 用途 | 数据源 |

| 1 | GET | `/health` | 服务、图、数据集状态 | 内存 |

## 3. 端点明细

### 3.1 `GET /health` — 服务与数据状态

用途：前端启动自检、答辩现场确认「图加载好了、数据齐了」。

```bash
curl http://127.0.0.1:8000/health
```

```json
{
  "status": "ok",
  "nodes": 979351,
  "edges": 2075761,
  "graph_loaded_at": 1793792964.23,
  "datasets": { "segments": 91203, "water_green": 3586, "pois": 5137 },
  "datasets_loaded_at": 1793792964.91
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 恒为 `"ok"`（失败时接口直接 5xx） |
| `nodes` / `edges` | int | 路网图规模，前台可显示「979,351 节点 / 2,075,761 条边」 |
| `graph_loaded_at` | number | 图加载完成的 unix 时间戳（秒） |
| `datasets` | object | 三个图层的行数；未加载成功时为 `null` |
| `datasets_loaded_at` | number | 数据集预热完成的 unix 时间戳（秒） |

> 数据集缺失不会阻止服务启动：`/health` 仍返回 200，但对应值为 `null`，
> 该图层的接口会返回 503；启动日志里会打印 `[api] WARNING dataset ...`。

### 3.2 `GET /api/layers` — 数据目录（前端先读它）

用途：判断图层是否就绪、拿字段中文名与 bbox、显示数据更新时间。
**前端不需要把字段名写死**，可以从这里生成图例。

```bash
curl http://127.0.0.1:8000/api/layers
```

```json
{
  "dataset": "running/v1",
  "crs": "EPSG:4326",
  "default_segment_bbox": [114.305, 30.508, 114.405, 30.562],
  "layers": {
    "segments": {
      "available": true,
      "endpoint": "/api/segments",
      "params": ["min_lng", "min_lat", "max_lng", "max_lat", "limit", "detail"],
      "count": 91203,
      "bbox": [113.442879, 29.795648, 115.212007, 31.613508],
      "geometry_type": ["LineString"],
      "basic_fields": ["osm_id", "fclass", "name", "length_m", "score", "grade",
                       "s_safety", "s_green", "s_slope", "s_cross", "s_fac", "s_air",
                       "no2_ugm3", "pm25_ugm3"],
      "fields": [{ "name": "score", "label": "综合分 0–100", "dtype": "float64" }],
      "notes": "detail=basic 返回 14 个评分字段；detail=full 返回全部属性。",
      "source": "data/processed/running/v1/segments.gpkg",
      "size_bytes": 46895104,
      "updated_at": "2026-11-04T08:12:31+00:00"
    },
    "water_green": { "available": true, "endpoint": "/api/water-green", "count": 3586,
                     "kinds": { "water": 2034, "green": 1552 } },
    "pois": { "available": true, "endpoint": "/api/pois", "count": 5137,
              "count_after_default_filter": 4146 }
  }
}
```

| 字段 | 说明 |
|---|---|
| `available` | `false` 表示源文件缺失；此时该层只有 `endpoint` 与 `error`，不会让整个接口 500 |
| `count` | 全量行数（不是 bbox 内） |
| `bbox` | 全量数据的 `[min_lng, min_lat, max_lng, max_lat]` |
| `geometry_type` | `LineString` / `Polygon` / `MultiPolygon` / `Point` |
| `fields[]` | `name` + `label`（中文）+ `dtype`；字段名就是响应里的键 |
| `basic_fields` | 仅 segments 有；`detail=basic` 实际返回的字段 |
| `count_after_default_filter` | 仅 pois 有；默认剔除休闲娱乐后的数量 |
| `source` / `size_bytes` / `updated_at` | 源文件相对路径、字节数、UTC 修改时间 |

用途：右栏脚注、图例、关于页；也是「这个分数怎么来的」的公开口径。

```bash
curl http://127.0.0.1:8000/api/meta
```

```json

               "cross": 0.10, "fac": 0.05, "air": 0.15 },
  "score_stats": { "count": 91203.0, "mean": 51.5, "std": 9.4, "min": 17.7,
                   "10%": 38.2, "50%": 52.8, "90%": 62.8, "max": 79.8 },
  "speed_mps": 2.78,
  "notes": ["坡度来自 SRTM 1\"，150 m 高斯平滑后求梯度；城区精度约 ±1 个百分点", "..."],
  "data": {
    "segments": "/api/segments",
    "segment_detail": "/api/segments/{osm_id}",
    "water_green": "/api/water-green",
    "pois": "/api/pois",
    "facilities": "/api/facilities",
    "catalog": "/api/layers",
    "crs": "EPSG:4326",
    "default_segment_bbox": [114.305, 30.508, 114.405, 30.562]
```

| 字段 | 说明 |
|---|---|
| `weights` | 六维权重，**合计 0.95**（沿用上一版口径，所以总分上限是 95） |

| `notes` | 五个维度的数据口径（答辩时逐条念得出来） |
| `data` | 前端可从这里取各图层 URL，不要散落硬编码 |

### 3.4 `GET /api/segments` — 评分底图（bbox 内路段）

```bash
curl "http://127.0.0.1:8000/api/segments?min_lng=114.352&min_lat=30.530&max_lng=114.366&max_lat=30.540&limit=1200"
```

| 参数 | 类型 | 必填 | 范围 | 默认 |
|---|---|---|---|---|
| `min_lng` / `min_lat` / `max_lng` / `max_lat` | float | 否 | 市域内，四参同给 | `114.305, 30.508, 114.405, 30.562` |
| `limit` | int | 否 | 1–60000 | 20000 |
| `detail` | string | 否 | `basic` / `full` | `basic` |

返回 `FeatureCollection`，顶层多四个字段：

```json
{
  "detail": "basic",
  "total": 8425,
  "truncated": false,
  "bbox": [114.305, 30.508, 114.405, 30.562],
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": {
      "osm_id": 1471868944, "fclass": "footway", "name": "",
      "length_m": 108.7, "score": 65.0, "grade": "较好",
      "s_safety": 95.0, "s_green": 76.2, "s_slope": 85.7,
      "s_cross": 0.0, "s_fac": 61.7, "s_air": 48.2,
      "no2_ugm3": 27.3, "pm25_ugm3": 36.6
    },
    "geometry": { "type": "LineString",
                  "coordinates": [[114.3546, 30.5342], [114.3547, 30.5344]] }
  }]
}
```

**`detail=basic`：14 个属性字段**（渲染底图 + 空气图层够用）：

```text
osm_id, fclass, name, length_m, score, grade,
s_safety, s_green, s_slope, s_cross, s_fac, s_air,
no2_ugm3, pm25_ugm3
```

**`detail=full`：26 个属性字段**，另含：

```text
walk_group, in_boundary, slope_mean_pct, elev_gain_m, tree_share, green_share,
d_green_m, d_water_m, d_main_m, d_fac_m, cross_200m, fac_500m
```

关键点：

- `score` 是路段六维加权分（0–100），**与 `/api/loops` 的偏好匹配分不是同一口径**；
- `grade` 取值：`差` / `一般` / `较好` / `好` / `很好`；
- `d_green_m` / `d_water_m` / `d_main_m` 的 **`null` 表示超出搜索半径**，不是 0；
- `pm25_ugm3` 只展示，不进评分；
- 一次别要太多：`limit=60000` 是硬上限，全市 91,203 段必然截断。底图按视口分块请求，
  或先用 `/api/layers` 的 `bbox` 取全市。
- 默认视口覆盖 PPT 原型那一屏（约 8,425 段）；城市级视野请显式传更大的 bbox。

着色建议：`score` 25–70 映射到 RdYlGn（色带见 `docs/过程/design-guidelines.md`）。

### 3.6 `GET /api/water-green` — 水体 / 绿地底图

```bash
curl "http://127.0.0.1:8000/api/water-green?min_lng=114.30&min_lat=30.50&max_lng=114.42&max_lat=30.58&kind=water&simplify=0.0002"
```

| 参数 | 类型 | 必填 | 范围 | 默认 |
|---|---|---|---|---|
| bbox 四个 | float | 否 | 四参同给 | 全市 |
| `kind` | string | 否 | `water` / `green` / `all` | `all` |
| `simplify` | float | 否 | 0–0.001（度） | `0`（不简化） |
| `limit` | int | 否 | 1–10000 | 10000 |

返回 `FeatureCollection`，顶层多：

```json
{
  "kind": "all",
  "total": 3586,
  "truncated": false,
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": { "kind": "water" },
    "geometry": { "type": "Polygon", "coordinates": [[[114.30, 30.55], "..."]] }
  }]
}
```

- 全量 3,586 面：水体 2,034、绿地 1,552；几何类型 `Polygon` 3,543 + `MultiPolygon` 43；
- `simplify=0.0002` 约 22 m，体积从 2.79 MB 降到约 2.4 MB；底图缩放较小时可用；
- 只传 `kind=water` 时 `total` 是过滤后的 2,034；
- 建议画在路网下面，配色见 `data/output/running/v1/web/README.md`。

### 3.7 `GET /api/pois` — 运动场馆点（推荐）

```bash
curl "http://127.0.0.1:8000/api/pois?min_lng=114.33&min_lat=30.515&max_lng=114.40&max_lat=30.570"
```

| 参数 | 类型 | 必填 | 取值 | 默认 |
|---|---|---|---|---|
| bbox 四个 | float | 否 | 四参同给 | 全市 |
| `kinds` | string | 否 | `sport` / `all` | `all` |
| `exclude_leisure` | bool | 否 | `true` / `false` | `true` |
| `limit` | int | 否 | 1–10000 | 10000 |

```json
{
  "kinds": "all",
  "exclude_leisure": true,
  "total": 4146,
  "truncated": false,
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": {
      "poi_id": "B0FFH...", "name": "Benefit Fitness",
      "type": "体育休闲服务;运动场馆;健身中心",
      "typecode": "080101", "address": "珞喻路...",
      "adname": "洪山区", "tel": "", "in_boundary": true
    },
    "geometry": { "type": "Point", "coordinates": [114.3518, 30.5640] }
  }]
}
```

- 全量 5,137 点；默认剔除台球/棋牌/游戏/歌舞/夜总会/网吧/KTV 后 **4,146** 点，
  与评分口径一致；`?exclude_leisure=false` 返回全量 5,137；
- `kinds=sport` 只保留 `type` 以 `体育` 开头的点；当前数据源本来就是运动场馆，
  因此 `sport` 与 `all` 的差别主要来自 `exclude_leisure`；
- **`kinds=support` 已明确返回 422**（不再静默返回全部）；洗手间/补给点数据尚未接入；
- `type` 是高德三级分类，多标签用 `|` 连接；前端截取最后一级做图例即可；
- `in_boundary` 表示是否在武汉市界内，默认不过滤（远城区点也保留）。

> 注意：`/api/pois` 的默认 `kinds=all` 是为了兼容旧调用；新前端建议显式写
> `kinds=sport&exclude_leisure=true`，语义更清楚。

### 3.8 `GET /api/facilities` — 设施点（旧版兼容别名）

保留给已经写好的前端，内部等价于 `/api/pois`，但：

| 参数 | 差异 |
|---|---|
| bbox 四个 | **必填**（旧版行为） |
| `kinds` | 默认 `sport`；只接受 `sport` / `all` |
| `exclude_leisure` | 没有该参数，**始终为 true** |
| `limit` | 1–10000，默认 10000 |

```bash
curl "http://127.0.0.1:8000/api/facilities?min_lng=114.33&min_lat=30.515&max_lng=114.40&max_lat=30.570"
```

返回结构与 `/api/pois` 完全一致（`kinds` / `exclude_leisure` / `total` / `truncated` / `features`）。
**新代码请直接用 `/api/pois`**，这个别名只为平滑迁移保留。

### 3.9 `POST /api/loops` — 生成候选环线

```bash
curl -X POST http://127.0.0.1:8000/api/loops \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,
       "prefs":{"green":1.0,"safe":1.0,"flat":0.6},"max_candidates":8}'
```

请求体：

| 字段 | 类型 | 必填 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| `lng` / `lat` | float | 是 | 市域内 | — | 起点（WGS84） |
| `target_m` | int | 否 | **1000–20000** | 5000 | 目标距离；算法侧能跑更远，但**接口当前上限 20 km** |
| `prefs` | object | 否 | 各 0–1 | `{green:1.0, safe:1.0, flat:0.6}` | `{green, safe, flat}`，影响代价函数 |
| `max_candidates` | int | 否 | 2–16 | 8 | 候选条数（越大越慢） |

返回（按 `rank` 升序，**第 1 条是推荐**）：

```json
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": {
      "length_m": 5339.5, "minutes": 32.0, "score": 78.5,
      "tree_share": 0.576, "slope_mean_pct": 3.55, "facility_m": 240.0,
      "origin_snap_m": 0.6,
      "sub": "{\"s_green\": 81.0, \"s_slope\": 64.5, \"s_safety\": 84.3}",
      "rank": 1
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3547, 30.5342], "...共 535 个点"] }
  }]
}
```

关键点（**前端最容易踩**）：

- `sub` 是 **JSON 字符串**，要 `JSON.parse(props.sub)` 才能拿到三个子分；只有
  `s_safety` / `s_green` / `s_slope` 三项（偏好匹配分，不是六维加权分）；
- `score` 是**偏好匹配分**（0–100），与 `/api/segments` 里的段分数**不同口径**，别混在一起排序；
- `origin_snap_m` 是起点吸附到路网的距离，> 100 m 时建议在 UI 上提示「起点离道路较远」；
- `minutes` 按 2.78 m/s 折算，未考虑红绿灯停留；
- 几何是**闭合环线**（首尾点相同）；
- 没有合适候选时返回 `features: []` + `message`，不是 404。

### 3.10 错误结构

**FastAPI 参数校验（422）**：

```json
{ "detail": [{ "type": "less_than_equal", "loc": ["query", "limit"],
               "msg": "Input should be less than or equal to 60000",
               "input": "99999", "ctx": { "le": 60000 } }] }
```

**bbox / 业务校验（422）** 的 `detail` 是字符串：

```json
{ "detail": "bbox 四个参数必须同时提供：min_lng / min_lat / max_lng / max_lat" }
```

**数据缺失（503）**：

```json
{ "detail": "data/processed/running/v1/segments.gpkg 不存在；请先运行 backend/scripts/build_running_dataset.py" }
```

| 场景 | 状态码 | `detail` 形态 |
|---|---|---|
| 数值越界（limit / target_m / max_candidates / simplify） | 422 | FastAPI 数组 |
| 缺必填字段 | 422 | FastAPI 数组 |
| bbox 只给一部分 / 边界反了 | 422 | 字符串 |
| `kinds=support` | 422 | FastAPI 数组（`literal_error`） |
| `osm_id` 不存在 | 404 | 字符串 |
| 源文件缺失/损坏 | 503 | 字符串 |
| 环线算法异常 | 500 | 字符串 |

前端展示时，`detail` 可能是字符串也可能是数组，建议：

```ts
const detail = body?.detail
const message = Array.isArray(detail) ? detail[0]?.msg : detail
```

## 4. 前端怎么联调

### 4.1 有后端

```powershell
# 1) 起后端（项目根目录）
.\.venv\Scripts\python.exe -m uvicorn app.api:app --app-dir backend --port 8000

```

前端代码只写相对路径：

```ts
// bbox 内评分路段
const q = new URLSearchParams({
  min_lng: '114.30', min_lat: '30.50',
  max_lng: '114.42', max_lat: '30.58',
  limit: '20000',
})
const segments = await fetch(`/api/segments?${q}`).then((r) => r.json())

// 水体 / 绿地
const waterGreen = await fetch('/api/water-green?kind=all&simplify=0.0002').then((r) => r.json())

// 运动场馆
const pois = await fetch('/api/pois?kinds=sport&exclude_leisure=true').then((r) => r.json())
```

> `frontend/app/src/api/client.ts` 目前只封装了旧版 5 个调用
> （`fetchHealth` / `fetchMeta` / `fetchSegments` / `fetchFacilities` / `fetchLoops`）。
> 新增的 `water-green`、`pois`、`layers`、单条路段请按上面的 URL 自行加一层封装；
> 本契约不要求前端改字段名。

### 4.2 没有后端（只写 UI）

`frontend/app/src/mocks/` 里放的是**旧版真实响应快照**，字段仍可用：

| 文件 | 对应接口 | 备注 |
|---|---|---|
| `health.json` | `GET /health` | 旧版没有 `datasets` 字段，前端做兼容 |
