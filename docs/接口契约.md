## 2. 通用结构

### 2.1 坐标与几何

- 全部 **WGS84 / EPSG:4326**，GeoJSON 坐标顺序 `[lng, lat]`；
- 长度、坡度在数据生产阶段用 **EPSG:32650** 计算，接口只返回结果；
- 百度地图需要 BD-09，**只允许在前端 `map/baiduAdapter` 边界转换一次**（`lib/coord.ts`），页面与接口层不得混用两套坐标。

### 2.2 成功与错误

| 场景 | 状态码 | body |
|---|---|---|
| 成功 | 200 | 见各端点 |
| 参数不合法（bbox 反向/越界、缺字段、数值越界） | **400 或 422** | 422 为 FastAPI 标准 `detail[]`；400 为 `{"detail":"..."}`（仅 `/api/segments` bbox 反向） |
| 数据文件缺失（gpkg / csv） | **503** | `{"detail":"..."}` |
| 算法异常（环线生成抛错） | **500** | `{"detail":"..."}` |
| 环线无候选 | **200** | `FeatureCollection` + `features: []` + `message`（**不是错误**） |

FastAPI 422 结构（前端取 `detail[0].msg` 即可）：

```json
{ "detail": [{ "type": "less_than_equal", "loc": ["query", "limit"],
               "msg": "Input should be less than or equal to 60000",
               "input": "99999", "ctx": { "le": 60000 } }] }
```

**错误模型不统一是已知缺口（G7）**：目前没有稳定的 `code` 字段，前端只能按 HTTP 状态码分类
（4xx = 参数/请求问题，5xx = 服务端/数据问题），文案直接展示后端 `detail`。

### 2.3 截断

只有 `/api/segments` 返回 `truncated`，实现为 `len(features) >= limit`。
注意边界：**恰好 `limit` 条时也会是 `true`**，前端应视为「可能还有」。处理方式：缩 bbox 或分块请求。

### 2.4 性能基线（2026-11-15 本机实测）

| 端点 | 条件 | 耗时 |
|---|---|---|
| `GET /health` | 图已加载 | 立即 |
| `GET /api/meta` | — | < 10 ms |
| `GET /api/segments` | 1200 段 | 约 0.6–0.7 s |
| `GET /api/facilities` | 216 点 | < 0.2 s |
| `POST /api/loops` | 5 km，`max_candidates=8` | **约 3.0–3.5 s**，返回 6 条 |

> 测试机：Windows + Python 3.13.7（embeddable）+ numpy 2.5 / scipy 1.18。
> 浏览器端首屏（含图加载与一次环线请求）约 5.5–5.8 s；首次请求未预热时更慢。
> 数字随机器与依赖版本波动，前端超时建议 ≥ 15 s，进度提示不要按 1 s 设计。

## 3. 端点详解

### 3.1 `GET /health` — 服务与图状态

```bash
curl http://127.0.0.1:8000/health
```

```json
{ "status": "ok", "nodes": 979351, "edges": 2075761, "graph_loaded_at": 1793792964.23 }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | 恒为 `"ok"`；失败时直接 5xx |
| `nodes` / `edges` | int | 图规模，前台可显示「979,351 节点 / 2,075,761 条边」 |
| `graph_loaded_at` | number | unix 时间戳（秒），进程加载图的时刻 |

---

### 3.2 `GET /api/meta` — 权重、分档、数据版本

```bash
curl http://127.0.0.1:8000/api/meta
```

```json
{
  "dataset": "running/v1",
  "weights": { "safety": 0.25, "green": 0.25, "slope": 0.15,
               "cross": 0.10, "fac": 0.05, "air": 0.15 },
  "score_stats": { "count": 91203.0, "mean": 51.5, "std": 9.4, "min": 17.7,
                   "10%": 38.2, "50%": 52.8, "90%": 62.8, "max": 79.8 },
  "speed_mps": 2.78,
  "notes": ["坡度来自 SRTM 1\"，150 m 高斯平滑后求梯度；城区精度约 ±1 个百分点", "..."]
}
```

| 字段 | 说明 |
|---|---|
| `weights` | 六维权重，**合计 0.95**（沿用上一版口径，总分上限 95） |
| `score_stats` | 全市 91,203 段分数分布；百分位键名是字符串 `"10%"`、`"50%"`、`"90%"` |
| `speed_mps` | 2.78 m/s（10 km/h），用于 `minutes` 换算 |
| `notes` | 五个维度的数据口径（答辩时逐条念） |

### 3.3 `GET /api/segments` — 评分底图（bbox 内路段）

```bash
curl "http://127.0.0.1:8000/api/segments?min_lng=114.352&min_lat=30.530&max_lng=114.366&max_lat=30.540&limit=1200"
```

| 参数 | 类型 | 必填 | 范围 | 默认 |
|---|---|---|---|---|
| `min_lng` / `min_lat` / `max_lng` / `max_lat` | float | 是 | 市域内 | — |
| `limit` | int | 否 | 1–60000 | 20000 |

返回 `FeatureCollection` + `truncated`：

```json
{ "type": "FeatureCollection", "truncated": true,
  "features": [{
    "type": "Feature",
    "properties": {
      "osm_id": 1471868944, "fclass": "footway", "name": "",
      "length_m": 108.7, "score": 65.0, "grade": "较好",
      "s_safety": 95.0, "s_green": 76.2, "s_slope": 85.7,
      "s_cross": 0, "s_fac": 61.7
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3546, 30.5342], [114.3547, 30.5344]] }
  }] }
```

**每要素 11 个属性 + geometry**（v1.0 文档写 12 是把 geometry 算进去了，以本表为准）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `osm_id` | int | OSM way id |
| `fclass` | string | 道路类型（footway / tertiary / residential…） |
| `name` | string | 路名，可能为空串 |
| `length_m` | float | 段长（EPSG:32650 量算） |
| `score` | float | 六维加权总分，0–95 |
| `grade` | string | `差` / `一般` / `较好` / `好` / `很好`（分箱 0/40/55/70/85） |
| `s_safety` / `s_green` / `s_slope` / `s_cross` / `s_fac` | float | 五个子分 0–100 |

已知缺口：**没有 `s_air` / `no2_ugm3` / 原始指标**（G2），因此前端「点击路段看六维 + 原始数据」目前做不了。

错误：bbox 反向/非法 → **400**；gpkg 缺失 → **503**；`limit` 越界 → 422。

### 3.4 `GET /api/facilities` — 设施点

```bash
curl "http://127.0.0.1:8000/api/facilities?min_lng=114.33&min_lat=30.515&max_lng=114.40&max_lat=30.570&kinds=all"
```

| 参数 | 类型 | 必填 | 取值 | 默认 |
|---|---|---|---|---|
| bbox 四个 | float | 是 | — | — |
| `kinds` | string | 否 | `sport` / `support` / `all` | **`sport`** |

```json
{ "type": "FeatureCollection",
  "features": [{ "type": "Feature",
    "properties": { "name": "Benefit Fitness", "type": "体育休闲服务;运动场馆;健身中心" },
    "geometry": { "type": "Point", "coordinates": [114.3518, 30.5640] } }] }
```

- `type` 是高德三级分号码，多标签用 `|` 连接；前端截最后一级作图例即可；
- 后端已剔除：`台球`、`棋牌`、`游戏`、`歌舞`、`夜总会`、`网吧`、`KTV`；
- **注意：`kinds` 目前被忽略**，任何取值都返回同一批（场馆）数据；语义上也没有 `kind` 属性（G4）。
  因此 UI 第 4 个开关「洗手间 / 补给点」只能当图层开关，不能当路径偏好。

错误：csv 缺失 → **503**。

### 3.5 `POST /api/loops` — 生成候选环线

```bash
curl -X POST http://127.0.0.1:8000/api/loops \
  -H "Content-Type: application/json" \
  -d '{"lng":114.3547,"lat":30.5342,"target_m":5000,
       "prefs":{"green":1.0,"safe":1.0,"flat":0.6},"max_candidates":8}'
```

请求体：

| 字段 | 类型 | 必填 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| `lng` / `lat` | float | 是 | 市域内 | — | 起点（WGS84） |
| `target_m` | int | 否 | **1000–20000** | 5000 | 目标距离；算法侧 1–42 km 可跑，接口上限 20 km（G5） |
| `prefs` | object | 否 | 各 0–1 | `{green:1.0, safe:1.0, flat:0.6}` | 影响代价函数；**三项不能全为 0**（权重和为 0 时综合分退化为 0，前端已守卫） |
| `max_candidates` | int | 否 | 2–16 | 8 | 越大越慢；5 km 约 3 s 出 6 条 |

返回（按 `rank` 升序，第 1 条为推荐）：

```json
{ "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "properties": {
      "length_m": 5339.5, "minutes": 32.0, "score": 78.5,
      "tree_share": 0.576, "slope_mean_pct": 3.55, "facility_m": 240.0,
      "origin_snap_m": 0.6,
      "sub": "{\"s_green\": 81.0, \"s_slope\": 64.5, \"s_safety\": 84.3}",
      "rank": 1
    },
    "geometry": { "type": "LineString", "coordinates": [[114.3547, 30.5342], "...共 535 个点"] }
  }] }
```

前端最容易踩的点：

- `sub` 是 **JSON 字符串**，必须 `JSON.parse(props.sub)`；只有 `s_safety` / `s_green` / `s_slope` 三项（偏好匹配分）；
- **`prefs` 三项全为 0 是未定义行为**：权重和 0 会导致 `score` 全为 0.0；前端必须至少保留一项（本项目在 `togglePref` 已拦截）；
- `score` 是**环线偏好匹配分**（0–100），与 `/api/segments` 的段加权分**不同口径**，不要混排；
- **没有 `grade`**（G3），前端徽标「很适宜/较适宜…」目前按 `score>=75/65/55` 本地判定；
- `origin_snap_m` 是起点吸附距离，> 100 m 建议提示「起点离道路较远」；
- `minutes` 按 2.78 m/s 折算，未考虑红绿灯停留（G6 同类）；
- 几何为**闭合环线**（首尾点相同），前端画线时白描边 9.2 px + `#141414` 5.3 px；
- **无候选时返回 HTTP 200**，`features: []`，并带 `message`（`to_geojson` 空结果分支）：

```json
{ "type": "FeatureCollection", "features": [],
  "message": "该起点在目标距离附近没有合适的折点，请换个距离或起点" }
```

错误：`target_m` 越界 / 缺 `lng` → 422；算法异常 → **500**。

## 4. 静态资产（不走接口）

底图与示例环线是**静态文件**，由 `frontend/app/scripts/sync-geo.mjs` 从 `data/output/running/v1/web/`
复制到 `frontend/app/public/geo/`（`npm run sync:geo`，`predev`/`prebuild` 自动执行；`public/geo/` 已 gitignore）。
构建后由 Vite 原样发布到 `/geo/*.geojson`。

| 文件 | 要素数 | 大小 | bbox（WGS84） | 用途 |
|---|---|---|---|---|
| `segments_city.geojson` | 8,005 | 1.81 MB | 114.305,30.508 → 114.405,30.562 | **默认底图**（与 PPT 一致） |
| `segments_arterial.geojson` | 19,298 | 7.16 MB | 同上（更全的路网） | 放大后替换底图 |
| `segments_all.geojson` | 90,193 | 29.12 MB | 全市 | 全城概览/热点图（默认不复制） |
| `water_green.geojson` | 3,586 面 | 2.43 MB | 同上 | 水系/绿地图层（`DRAW_WATER_GREEN=false`，默认不画） |
| `loops.geojson`（示例输出） | 6 条 | 0.9 MB | 武大 5 km | 演示/离线配色参考 |

属性：底图与 `/api/segments` 同构（11 属性 + geometry，score 为 0–100 整数）；
`water_green` 面属性 `{kind:"water"|"green"}`。

> 为什么不用接口画底图：8,005 段一次 fetch 很慢且后端无缓存；静态文件可 gzip、可 CDN，且与后端解耦。

## 6. 已知缺口与限制（G1–G8）

| # | 问题 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| **G1** | 无 `mode`，单行线只存在于 `build/demo_routes.py:135` | 未实现 | UI「单行线 A→B」只能置灰 | 后端加 `mode`，返回 `destination`/`closed:false` |
| **G2** | `/api/segments` 无 `s_air`、无原始指标、无单段端点 | 未实现 | 点击路段讲不清「为什么低分」 | 新增 `GET /api/segments/{osm_id}` |
| **G3** | `/api/loops` 无 `grade`，且与 segments 的 score 两套口径 | 未实现 | 徽标只能前端硬编码 | loops 返回 `grade` + `score_kind`，或 meta 给两套分档 |
| **G4** | `/api/facilities` 的 `kinds` 被忽略、无 `kind` 字段 | 未实现 | 第 4 个开关只能是图层 | 实现 `sport\|support\|all` 并回 `kind` |
| **G5** | `target_m` 上限 20 km | 保留 | 产品口径 1–42 km 不一致 | 不改（3/5/10 km 已够），文档写明 |
| **G6** | 无地理编码；无 AK 时搜索不可用 | 替代方案 | 搜索框只能搜预设点 | BMapGL `LocalSearch`（需 AK）；无 AK 用 2 预设 + 地图点选 |
| **G7** | 错误码 400/422/500/503 混杂，无 `code` | 保留 | 前端只能按状态码粗分 | 统一 `{code,message,hint}`，前端先兼容 |
| **G8** | 静态底图不在 Vite root，构建后 404 | **已解决** | — | `sync-geo.mjs` + `public/geo/`（已 gitignore） |

其它口径限制（不是 bug）：`minutes` 不含红绿灯；`weights` 合计 0.95；`origin_snap_m` 显示真实值（0.6 m → 显示 1 m）；地图是 WGS84 线性投影，与 PPT 的 matplotlib/UTM 底图有 1 px 级抗锯齿差。

## 9. 字段字典

### 9.1 Segment properties（`/api/segments` 与静态底图）

| 字段 | 类型 | 空值 | 单位 | 说明 |
|---|---|---|---|---|
| `osm_id` | int | — | — | OSM way id |
| `fclass` | string | 无 | — | 道路等级 |
| `name` | string | `""` | — | 路名 |
| `length_m` | float | — | m | 段长 |
| `score` | float | — | 0–100 | 六维加权（上限 95） |
| `grade` | string | — | — | 差/一般/较好/好/很好 |
| `s_safety` | float | — | 0–100 | 安全 |
| `s_green` | float | — | 0–100 | 绿化 |
| `s_slope` | float | — | 0–100 | 坡度 |
| `s_cross` | float | — | 0–100 | 过街 |
| `s_fac` | float | — | 0–100 | 设施 |

### 9.2 Loop properties（`/api/loops`）

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `rank` | int | — | 1 起，1 为推荐 |
| `length_m` | float | m | 总长（含回程） |
| `minutes` | float | min | `length_m / 2.78 / 60`，不含红绿灯 |
| `score` | float | 0–100 | 环线偏好匹配分（≠ 段分） |
| `tree_share` | float | 0–1 | 树冠覆盖占比 |
| `slope_mean_pct` | float | % | 平均坡度 |
| `facility_m` | float | m | 到最近场馆距离 |
| `origin_snap_m` | float | m | 起点吸附距离 |
| `sub` | **string** | — | JSON 字符串：`{s_safety,s_green,s_slope}` |

| 对象 | 字段 |
|---|---|
