# 数据现状与增补建议

> 目的：回答两个问题——**当前评价系统到底吃了哪些数据**、**为了让评价更好还应引入什么数据**。
> 本文的结论以仓库内实测为准（2026-10-27 现算），不是文献综述。
> 相关文档：`docs/数据/数据字典-跑步数据集.md`（字段）、`docs/数据/数据补充清单.md`（可得性口径）、
> `docs/过程/验证与敏感性分析.md`（权重敏感性）。

---

## 0. 结论先行

**评价系统的瓶颈不在"数据太少"，而在"已有数据没用上、两个维度定义错了"。**

按投入产出排序，正确的做法是：

| 优先级 | 做什么 | 新增采集成本 | 预期收益 |
|---|---|---|---|
| **P0** | 修 `s_fac` / `s_cross` 的定义错误 | 零 | 最高：直接救活两个已失效维度 |
| **P0** | 从本地 `hubei-261013.osm.pbf` 重抽 `surface` / `lit` / `sidewalk` / `cycleway:*` / `maxspeed` | 零（文件已在硬盘） | 高：新增"舒适度"维度、骑行安全从"道路等级"升级到"机非隔离" |
| **P1** | 启用 `d_water_m` + 线状水系，新增滨水维度 | 零（已算好，躺在表里） | 高：武汉"百湖之市"，当前完全没用 |
| **P1** | 补公开栅格：地表温度 / 人口 / 空气质量 | 低（GEE 等公开源） | 中：补"热舒适""拥挤度""空气"三个真实痛点 |
| **P2** | 高德交通态势（需商务申请，仅实时快照） | 中 | 低-中：只能做多日采样代理车流量 |
| **P2** | 20–30 段实地打分 | 人力 | **不可替代**：唯一能把权重从"拍脑袋"变成"有锚"的手段 |

最后一行的意思很直接：遥感与开放数据能补"环境"，但补不了"人"。这与
`docs/数据/数据补充清单.md` 的既有口径一致——**真实约束不是没有数据，而是没有人的数据**。

## 2. 现有评分的四个结构性问题（带实测数字）

### 2.1 设施维度已经实质失效——它在给所有路段加同一个常数

- `s_fac` 中位 **3.0**，`s_fac < 0.5` 占 **45.1%**，`< 10` 占 **55.7%**；
- `d_fac_m` 中位 **1,760 m**、p75 12,150 m、max 71,290 m；
- **71.2%** 的路段 500 m 内**一个**设施点都没有（`fac_500m == 0`）。

原因不是数据缺失，而是**指标选错了对象**：运动场馆是"今天去哪练"的目的地，
而跑者途中需要的是**饮水、厕所、便利店、座椅、避雨**。全市 3,126 个 `pitch` +
4,081 个高德场馆撒在 8,500 km² 上，中位距离必然 >1 km，经 `100·exp(-d/500)`
衰减后恒等于 0~3 分。

**后果**：总分上限被压死。三项（绿化/坡度/过街）接近满分时，
`s_fac≈3` 让理论最高分只有约 **72**，实测 `score` 最大值 **85.9**、
分档"很好"仅 **1 段**——这不是"武汉没有好路段"，是评分函数不可达。

### 2.2 过街维度方向反了——它在奖励"路口多"

`s_cross = clip(100 − 7×cross_200m)`，即 200 m 内分叉点越多分越低……
但 `cross_200m` 的物理含义是"步行图顶点度 ≥3 的节点数"，包含公园内部小径分叉，
与"要不要等红灯横穿马路"基本无关：

- 与 OSM 实测 `pedestrian_crossing`（200 m 内）Spearman 仅 **0.373**；
- 与 `traffic_signals` 仅 **0.213**；
- `cross_200m` p99 = **201**、max = **429** —— 200 m 半径内 429 个分叉点，物理上不成立；
- 分布双峰：**29.6%** 的路段 `s_cross` 直接为 0（分叉点 ≥15 个，秒杀），
  另一端是空旷路段满分。中间没有过渡。

对跑步体验而言，"路口多"本身就是**负面**（停顿、吸尾气、横穿风险），
现在的函数方向恰好把它当成正面。应改为**惩罚缺失**：无隔离横穿主干道扣分、
过街间距过小扣分，而不是"分叉点越多越好"。

### 2.3 坡度对九成路段无区分度，安全只有道路等级

- `slope_mean_pct` 中位 **1.19%**、p90 **3.27%**；>6% 仅 **3.31%**，>10% 仅 **1.01%**；
- `s_slope` 中位 **88.1** —— 20% 的权重压在一条几乎不分档的指标上；
- `s_safety` 只有"道路等级查表 + 距主干道 15/10 分扣分"，无法区分
  "有独立非机动车道的主干道"与"无非机动车道的主干道"。

### 2.4 市域与建成区混在一张表里算

`in_boundary = False` 的路段 **26,415 段（29.0%）** 均值 46.7，`True` 均值 52.6。
这些是 bbox 内、主城区界外的乡道与县道。它们与东湖绿道共用一把尺子，
既拉低全局分布，也让"设施分低"看起来像系统性缺陷。
建议报告与前端**分区统计/分区评级**，或至少显式区分"城市慢跑"与"郊野路线"两种场景。

## 4. P1：公开栅格与开放数据（免费、可复现）

选型原则：只补现有五维**测不到、但跑者真实感知**的东西。

| 数据 | 分辨率 / 重访 | 许可 | 补什么 | 预期增益 | 局限 |
|---|---|---|---|---|---|
| **Landsat 8/9 C2 L2 地表温度** | 30–100 m / 16 天 | 公开 | 夏季热舒适、树荫的实际降温效果 | 高（武汉夏季是首要痛点） | 云污染，需多时相合成 |
| **WorldPop 人口** | 100 m / 年 | CC-BY 4.0 | 拥挤度代理；设施应按"人"加权而非按"面积" | 高 | 仅居住地，非实时人流 |
| **国控空气质量站小时值** | 站点 / 1 h | 公开网页 | PM2.5 / O3 → 空气分或"今日不建议跑" | 中 | 武汉仅约 10 站，需插值；无官方 API |
| **Sentinel-2 NDVI** | 10 m / 5 天 | 公开 | 植被活力 | **低（不建议优先）** | 与 WorldCover 高度共线，边际收益小 |
| **Sentinel-5P TROPOMI NO2** | ~1 km（L3）/ 日 | 公开 | 街道级交通排放 | 低-中 | 1 km 尺度，比路段粗一个量级 |
| **VIIRS 夜光 VNP46A2** | 500 m / 月 | 公开 | 夜间照明/安全感 | 中 | 中心城区饱和，区分度有限 |
| **OSM 建筑（142,385 栋）** | 面 | ODbL | 建筑密度 → 街道峡谷、遮阴与风 | 中 | 依赖 OSM 覆盖 |
| **ERA5-Land 气温/降水** | 9 km / 1 h | 公开 | 分时段历史体感温度 | 中 | 粗，只适合做时间维度而非路段维度 |

**不建议优先的世界覆盖类重做**：WorldCover 10 m 已是当前树冠的来源，
换成 Dynamic World / ESA CCI 不会改善"不识别单排行道树"这一根本限制——
那是分辨率问题，只有街景或 LiDAR 才能解，而两者都不可得。

## 5. P2：需申请、需采样、以及明确不可得

### 5.1 可争取

- **高德交通态势查询**（`/v3/traffic/status/rectangle`）：官方文档确认**支持武汉**，
  但属"高级服务接口，需商务咨询/付费申请"，且**只返回实时快照、无历史**。
  可行方案：选 30–50 条代表性干道，连续采样 3 天 × 12 个时段，
  得到"日间平均拥堵指数"作为车流量代理。**不能全量标定**，只能做局部校准。
- **天气 API**（高德/和风，有免费额度）：不是路段属性，而是**会话级**建议
  （"今天 35 ℃，建议东湖绿道树荫段"）。评分系统本身不需要，但前端体验提升明显。

### 5.2 不可得（维持既有口径，不要反复尝试）

| 数据 | 结论 | 依据 |
|---|---|---|
| 街景影像 | 不可得 | 百度/高德无公开街景 API；腾讯需企业认证；Mapillary 中国区稀疏且约十年前 |
| 路段车流量 | 无公开数据 | 交管数据不开放；高德态势仅实时快照 |
| 真实跑步/骑行轨迹 | 无公开接口 | Strava 中国区几乎无数据且需授权；共享单车热力无开放 API |
| 手机信令人流 | 不可得 | 运营商数据，需商业合作 |
| 官方全市健身设施 | 仅江岸区有 | `docs/数据/数据补充清单.md` |

### 5.3 唯一能"锚定"权重的办法：小规模实地打分

遥感解决"环境"，解决不了"人觉得好不好跑"。建议：

- 选 **20–30 段**（覆盖：东湖绿道 / 江滩 / 老城窄巷 / 主干道旁人行道 / 郊野公路 / 高架桥下），
  每段 200–500 m，实地按 5 维各打 0–100 分（2 人独立打分取均值，算一致性）；
- 用这组人工分做**外部对照**：算与当前 `score` 的 Spearman、看哪一维偏差最大；
- 用简单回归/网格搜索重标 `W`，把"拍脑袋权重"换成"有 30 个锚点的权重"。

这比再加十个遥感图层更能说服答辩老师，工作量约 1–2 天。

## 6. 建议的指标改造（具体到公式）

### 6.1 重写 `s_fac`：从"到最近场馆"改为"沿途服务可用性"

```
serve = 2.0·n(饮水, 300m) + 1.5·n(厕所, 300m) + 0.5·n(座椅/避雨, 300m)
      + 0.3·n(便利店/超市, 500m) + 0.2·n(公交站, 500m)     # 撤退能力
s_fac = 100 · (1 − exp(−serve / 3))
```
- 用 `fac_500m` 的同一套树，换半径即可；饮水/厕所/座椅在 OSM 里稀少（9/125/46），
  需与高德 POI 合并；
- 若仍稀疏，就**降权**：`w_fac 0.10 → 0.05`，把 0.05 让给安全或新增的舒适度。
- 同时按 WorldPop 做需求加权：人口稀疏的郊野段不该因"没便利店"被重罚。

### 6.2 重写 `s_cross`：从"密度奖励"改为"过街惩罚"

```
若路段 50 m 内无需横穿机动车道：            s_cross = 100
否则：
  d = 到最近 pedestrian_crossing / traffic_signals 的距离
  s_cross = 100·exp(−d/120) − 20·[横穿的是 primary 及以上]
```
- "是否需要横穿"用 `gis_osm_roads_free` 的机动车等级判定，而不是步行图分叉点；
- 附带修掉 `cross_200m` 的失真：改用**机动车交叉口**计数，并封顶（如 20），
  避免 429 这种值。

### 6.3 新增 `s_water`（滨水）——零成本

```
s_water = 100·exp(−d_water/400)，其中 d_water = min(面状水体, 线状河渠)
```
武汉的跑步价值高度集中在两江、东湖、沙湖、汤逊湖沿岸；`d_water_m` 已算好，
只差一个公式。建议权重 0.10（从 `s_fac` 挪）。

### 6.4 新增 `s_comfort`（路面与遮蔽）——PBF 抽取后可得

```
s_comfort = 0.45·铺装分(surface, smoothness)
          + 0.25·遮阴分(tree_share)               # 与 s_green 共享但独立计权
          + 0.20·照明分(lit, 夜间场景)
          + 0.10·隔离分(sidewalk / cycleway)
```
跑步侧关注"膝踝负担 + 遮阴"，骑行侧关注"铺装 + 机非隔离"，两者权重不同。

### 6.5 新增 `s_heat` / `s_air`（可选，答辩加分项）

```
s_heat = clip(100·(1 − (LST_summer − 28)/12))      # 夏季地表温度
s_air  = clip(100·(1 − PM2.5/75))                  # 国控站 IDW 插值
```
这两维对"今天适不适合跑"的解释力强于对"哪条路更好"的区分力，
更适合做**前端提示**而非核心权重。

### 6.6 骑行专属修正

| 项 | 现状 | 建议 |
|---|---|---|
| 坡度 | 平均坡度，`SLOPE_ZERO=6` | 改**累计爬升**（`elev_gain_m` 已有）+ 最大坡度；武汉平坦，平均坡度无区分度 |
| 路面 | 未做（OSM 覆盖 4.3%） | 用 PBF 重抽后覆盖会上升；碎石/土路对公路车直接扣到底 |
| 机非隔离 | 仅 `fclass=cycleway` 加分（927 段） | 用 `cycleway:left/right/both` 区分"专用道/划线/混行"三档 |
| 车速 | 未用 | `maxspeed` + `lanes` |
| 终点设施 | 无 | `bicycle_parking`（OSM 仅 38 个，太稀；改用高德 POI） |

### 6.7 建议的权重表（v2 草案，标注依据）

| 维度 | 现权重 | 建议 | 理由 |
|---|---:|---:|---|
| 安全 | 0.30 | 0.28 | 加入 sidewalk/隔离后仍是最重 |
| 绿化 | 0.25 | 0.20 | 与 `s_comfort` 的遮阴项部分重叠，避免双计 |
| 坡度 | 0.20 | 0.12 | 实测中位 88 分，20% 权重压在无区分度指标上 |

## 9. 一句话给答辩

> 我们的数据不是"越多越好"，而是**每一维都要说清它是谁的真实体验的代理、误差朝哪个方向偏**。
> 现有系统的最大问题不是缺卫星影像，而是：设施维度用"到场馆的距离"替代"沿途有没有水喝"，
> 过街维度用"路口多不多"替代"要不要闯红灯"——这两处修好，比再叠三层遥感更有效。
