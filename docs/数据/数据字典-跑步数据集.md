# 数据字典 — 慢跑适宜性数据集（running/v1）

生成脚本：`backend/scripts/build_slope.py` → `build_canopy.py` →
`build_running_dataset.py` → `run_loop_demo.py`
上游基础数据见 `docs/数据/数据字典-v1.md`（路网、公交、地铁、POI）。

> `data/processed/running/v1/` 每次跑 `build_running_dataset.py` 会**覆盖**
> `segments.gpkg`，但不会删除 `.csv`。字段说明以本文件为准。

---

## 1. `segment_slope.csv`（91,203 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `osm_id` | int | OSM way id，与 `osm_walk_roads.gpkg` 对应 |
| `length_m` | float | 段长（米，EPSG:32650） |
| `slope_mean_pct` | float | 长度加权平均坡度（%），来自 150 m 平滑后的 DEM 梯度 |
| `slope_max_pct` | float | 沿线最大坡度（%），封顶 30 |
| `elev_gain_m` | float | 正向累计爬升（米） |
| `elev_min_m` / `elev_max_m` | float | 高程范围（米） |

> 30 m DEM 在城区有 ±4 m 噪声，逐点差分会得到 5–7% 的假坡度，
> 因此先平滑再求梯度；结果是**地形趋势**，不是单点路面的真实坡比。

## 2. `segment_canopy.csv`（91,203 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `osm_id` | int | 同上 |
| `tree_share` | float | 120 m 窗口内 tree cover 像元占比（0–1） |
| `green_share` | float | 窗口内绿地类（tree/shrub/grass/crop）占比（0–1） |
| `tree_share_max` | float | 沿线最大单点树冠占比（0–1） |

来源：ESA WorldCover 2021 v200，10 m。**反映成片林荫**，
单排行道树常不足一个像元，会被低估。

## 3. `amap_sport_poi.csv`（5,137 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `poi_id` | str | 高德 POI id |
| `name` | str | 名称 |
| `type` | str | 三级类型，如 `体育休闲服务;运动场馆;健身中心` |
| `typecode` | str | 类型编码，如 `080111` |
| `lng_gcj02` / `lat_gcj02` | float | 高德原始坐标（GCJ-02） |
| `lng` / `lat` | float | 转换后的 WGS84，**计算与绘图用这组** |
| `address` | str | 地址 |
| `adname` / `adcode` | str | 区名 / 行政区码 |
| `tel` | str | 电话（多为空） |
| `in_boundary` | bool | 是否在武汉市界内（4,992） |

评分前会剔除台球厅/棋牌室/游戏厅/歌舞厅等室内娱乐（剩 4,081）。

### 3.1 `amap_toilet_poi.csv`（6,122 行）

2026-11-17 用高德 `place/around` 关键字搜索补抓的公共厕所，字段与运动场馆表一致
（`poi_id` / `name` / `type` / `typecode` / `lng_gcj02` / `lat_gcj02` / `lng` / `lat` /
`address` / `adname` / `adcode` / `tel` / `in_boundary`）。

- 283 个 0.06° 网格 × 4.5 km 半径，关键字 `公共厕所|公厕|厕所|卫生间|洗手间`；
- 6,122 个唯一 POI，界内 5,959 个；
- 类码以 `200300`（公共厕所）为主，另有 `200301/200302/200303`（男/女/无障碍洗手间）。

合并进 `poi.gpkg` 时过滤掉商户/办公点/暂停营业，保留 **5,839 个**（`toilet` 5,117 +
`toilet_indoor` 722），脚本 `backend/scripts/merge_amap_toilet_poi.py`。

## 4. `segments.gpkg` → 图层 `segments`（91,203 行）

一行 = 一个 OSM 路段（LineString，WGS84），带全部指标与评分。

### 4.1 基础

| 字段 | 说明 |
|---|---|
| `osm_id` | OSM way id |
| `fclass` | 道路类型（footway / residential / primary …） |
| `name` | 路名（可能为空） |
| `length_m` | 长度（米） |
| `walk_group` | `foot`（纯步行道）/ `street`（可步行道路） |
| `in_boundary` | 中点是否在市界内 |

### 4.2 原始指标

| 字段 | 说明 |
|---|---|
| `slope_mean_pct` / `elev_gain_m` | 坡度与爬升 |
| `tree_share` / `green_share` | 树冠 / 绿地覆盖 |
| `d_green_m` | 到最近绿地多边形距离（米），未命中为 inf |
| `d_water_m` | 到最近水体距离（米） |
| `d_main_m` | 到最近主干道（primary/secondary/trunk/motorway）距离（米） |
| `d_fac_m` | 到最近设施点的距离（米）。设施 = 高德运动场馆 4,081 + OSM 公园/厕所/便利店 5,344 + 高德公厕 5,117，共 **14,542** |
| `cross_200m` | 200 m 内路口数（图顶点度 ≥3） |
| `fac_500m` | 500 m 内设施计数（参考值，评分用 `d_fac_m`） |
| `no2_ugm3` | 年均 NO₂ 浓度（µg/m³），来自 CHAP 1 km 网格（2024 年） |
| `pm25_ugm3` | 年均 PM2.5 浓度（µg/m³），同上；**只展示，不进评分** |

### 4.3 子分与综合分（0–100）

| 字段 | 权重 | 计算 |
|---|---:|---|
| `s_safety` | 0.36 | 道路等级映射；距主干道 <50 m 再扣 15、<20 m 再扣 10 |
| `s_green` | 0.26 | `0.7 × 树冠指数分 + 0.3 × 到绿地距离分` |
| `s_slope` | 0.06 | `100 × (1 − slope/10)`，10% 及以上为 0 |
| `s_cross` | 0.15 | `100 − 7 × 路口数`，下限 0 |
| `s_fac` | 0.06 | `100 × e^(−d_fac/500)` |
| `s_air` | 0.11 | `100 × (40 − NO₂) / 30`，**10 µg/m³（WHO 2021 指导值）→ 100，40 µg/m³（GB 3095 二级）→ 0**，截断到 0–100 |
| `score` | — | 六项加权和（权重合计 **1.00**，v2 口径 2026-11 定版，即六维加权平均、满分 100） |
| `grade` | — | 差 <35 / 一般 35–50 / 较好 50–65 / 好 65–80 / 很好 ≥80（`pd.cut(include_lowest=True)`，边界值归下档） |

> **口径变更（2026-11-17）**：旧 v1 口径权重合计 0.95、分档 40/55/70/85。
> 改成 1.00 是因为 0.95 让"综合分"变成上限 95 的加权和、不好解释；
> 分档线重定是因为旧 85 线高于全网最高分（89.9），"很好"档恒为空。
> 现网分布：mean 52.0 / std 12.4 / 中位 54.1 / min 13.0 / max 89.9，
> 分档 差 10,304 / 一般 23,875 / 较好 45,370 / 好 11,305 / 很好 349。

> **空气为什么只做区域校正**：2024 年年均 NO₂ 在中心（<2 km）与外围（>40 km）之间差 28.8 vs 18.9 µg/m³（1.5 倍），
> 但同一圈层内主干道 / 居住区 / 人行道之间只差 0.2–1.8 µg/m³（约一个数量级更小）。
> PM2.5 更是没有空间梯度（1.09 倍），所以只保留在表里做展示，不进子分。
> 详见 `data/output/running/v1/demo/docs/项目交接说明.md`。

## 5. `loops.geojson`

每个 Feature 是一条闭合环线（LineString，WGS84）：

| 属性 | 说明 |
|---|---|
| `origin` / `label` | 起点标识与名称 |
| `rank` | 该起点的候选排序（1 最好） |
| `length_m` / `minutes` | 长度与预计用时（10 km/h） |
| `score` | 环线综合分（按偏好权重的子分加权） |
| `tree_share` | 沿线树冠覆盖率（长度加权） |
| `slope_mean_pct` | 沿线平均坡度 |
| `facility_m` | 沿线到最近设施的平均距离 |
| `sub` | JSON 字符串：`s_safety` / `s_green` / `s_slope` |

## 6. 与 `v1` 基础数据集的关系

| 数据 | 来源 |
|---|---|
| 路网几何 | `data/processed/v1/osm_walk_roads.gpkg` |
| 绿地/水体面 | `data/raw/hubei/.../hubei.gpkg`（landuse / water 图层） |
| POI（公园/厕所/便利店/高德公厕） | `data/processed/v1/poi.gpkg` |
| 公交地铁（接驳，可选） | `data/processed/v1/stops_*.csv` |

`running/v1` 不复制这些基础数据，只保存派生结果，避免仓库里存两份几何。

## 7. 空气数据（`segment_air*.csv` / `air_monthly_*.csv`）

由 `backend/scripts/build_air_quality_chap.py`（年均）与 `build_air_monthly.py`（逐月）生成，
数据源是 CHAP（ChinaHighPM2.5 / ChinaHighNO2）1 km 网格，托管在 Zenodo，公开免费、无需注册。

| 文件 | 行数 | 字段 |
|---|---:|---|
| `segment_air.csv` | 91,203 | `osm_id`、`length_m`、`in_boundary`、`pm25_ugm3`、`no2_ugm3`（2024 年均） |
| `segment_air_pm25.csv` / `segment_air_no2.csv` | 91,203 | 单产品，字段同上 |
| `segment_air_monthly.csv` | 91,203 | `osm_id` + `pm25_YYYYMM` × 12 |
| `air_monthly_wuhan.csv` | 12 | `month`、`pm25_median`、`pm25_p10`、`pm25_p90`、`pm25_mean`、`pm25_p95`、`seg_nan`、`seg_median` |
| `air_quality_stations.csv` | 19 | AQICN 实测站点（10 个在市界内），字段见脚本头 |

**口径提醒**

- CHAP 是**再分析产品**（站点 + 卫星 + 模式融合），不是实测；年均值对「某一条路」只能到 1 km。
- 网格值按**路段中点**取样，单位 µg/m³（NetCDF 里是 uint16 × `scale_factor=0.1`，nodata 65535）。
- 年度文件约 5–6 MB，月度 6–8 MB；下载中断会留下「大小正常但读不了」的文件，脚本用
  `rasterio.open` 试读校验后重下。
- 2024 年 PM2.5 月均：1 月 66.6、7 月 12.7、11 月 38.5 µg/m³ → **月份差 5.2 倍**，远超同月空间差（1.1–1.3 倍）。
